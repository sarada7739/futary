# 046: アルバムの写真を ZIP で持ち出す

## 目的

**人間の指示。有料をやめたとき、無料枠を超える写真は取り上げる（047）。その前に、写真を全部まとめて持ち出せる必要がある。**

- **アルバム 1 つ**、または **作ったアルバム全部**を、1 つ以上の ZIP で保存する
- iPhone では「ファイル」に落ちる。**それでよい**（持ち出しが目的。写真ライブラリに入れるのは 042 の共有シート）
- 042 で ZIP を落とした理由（写真ライブラリに入らない）は、この用途には当てはまらない

## 0. 方式（A が先に決めた）

| | |
|---|---|
| どこで組むか | **ブラウザ**（`fetch` → `fflate` の `zipSync`、無圧縮 `level: 0`）。Worker は通さない（無料枠の CPU 10ms で CRC32 を全バイトに掛けられない） |
| ライブラリ | **`fflate`** を `apps/app` に足す（依存 0・約 8KB）。B が段階0で Expo Web のバンドルで動くことを確かめる |
| 1 つの ZIP の上限 | **100 枚**。超えるアルバムは 100 枚ずつ複数の ZIP（`…-1of3.zip`）。iPhone の Safari で 100 枚（30〜60MB）が落ちないかは段階0（人間の iPhone）。落ちるなら 50 |
| 前提 | R2 の CORS（GET・アプリのオリジン）は 042 で確認済み。CSP の `connect-src` も済み |
| 中のファイル名 | 041 の `filename`（`futary-YYYYMMDD-{imageId}.jpg`）。**説明文（caption）は `captions.txt` に 1 行 1 枚で同梱**（写真だけ持ち出して文が消えるのは持ち出しではない） |
| ZIP の名前 | `futary-{アルバム名を安全な文字に}-{YYYYMMDD}.zip`。全部のときは `futary-albums-{YYYYMMDD}-1of3.zip`。`/ \ : * ? " < > |` を `_` に |

## 1. 画面

| 場所 | 何 |
|---|---|
| アルバム詳細のヘッダー `⋯`（新設。編集・選択の隣） | **「ZIP で保存」**（`canShare` に関係なく出す。PC でも iPhone でも） |
| アルバム一覧のヘッダー `⋯`（新設） | **「すべての写真を ZIP で保存」**（作ったアルバム全部。タイムラインは含めない。投稿の写真は投稿のもの） |
| マイページ | 045 の「プラン: 無料／有料」の行の下に **「アルバムの写真をまとめて保存」**（一覧の `⋯` と同じ動作）。047 の猶予の案内から飛ぶ先 |

- 押すと確認: 「38 枚を ZIP で保存します（約 15MB）」→「保存」。概算は枚数 × 400KB
- 進捗「12 / 38 枚を取得中…」。**途中で閉じられる**（`AbortController`。Blob を捨てる）
- 取れなかった枚は飛ばして続け、最後に「2 枚は保存できませんでした」
- 100 枚を超えるときは「3 つのファイルに分けて保存します」と先に出し、順に `<a download>`（ブラウザが「複数のダウンロードを許可」を聞くことがある。**1 つずつ、前のが始まってから次**）
- ゲストも押せる（041・042 と同じ理由）
- `photo.list` を `limit` 60 で辿って集める。`photo.downloadUrl` を枚数ぶん呼ぶ（042 と同じ。1 リクエスト 1 署名）

## 2. 段階0（B。結果を `artifacts/046/spike.md`）

1. `fflate` が Expo Web のバンドルで動く（ローカル）
2. 人間の iPhone（本番）: 100 枚の ZIP が「ファイル」に落ちる。落ちるなら 50
3. PC のブラウザ: 3 つの ZIP が順に落ちる

**2 と 3 は実装してデプロイしてから人間に頼む**（043・045 と同じ順）。

## 3. やらないもの

| | 扱い |
|---|---|
| Worker 側の ZIP | しない |
| 圧縮 | しない（JPEG は縮まない） |
| タイムラインの写真を含める | しない（投稿は消えない。持ち出しの対象は取り上げられるアルバムの写真） |
| 選んだ写真だけ ZIP | しない。アルバム単位・全部。選んだ写真は 042 の共有シート |
