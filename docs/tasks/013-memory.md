# 013: 思い出し

## 目的
過去の投稿を掘り起こしてホームに出す。
「時間が経つほど価値が増す」というこのアプリの核心にあたる機能。

## 実装内容

**日付は `packages/date` を使う。存在しない日はその月の末日に寄せる**
（`architecture.md` 5節）。3月31日の「1ヶ月前」は **2月28日**であり、
素の `Date` が返す 3月3日ではない。

**3月29日・30日・31日の「1ヶ月前」は3日とも2月28日になる。**
同じ投稿が3日続けて出ることがあるが**不具合ではない。**

**4段の探索すべてに `AND deleted_at IS NULL` を含める**（`architecture.md` 4節）。
忘れると**削除した投稿がホームの最上部に「思い出」として復活する。**
消したという操作が、最も目につく場所で裏切られる。


### 探索順（ADR-006 / `docs/architecture.md` 5節）
```
1. ちょうど1ヶ月前の投稿          -> ラベル「1ヶ月前の今日」
2. ちょうど半年前の投稿            -> ラベル「半年前の今日」
3. ちょうど1年前の投稿             -> ラベル「1年前の今日」
4. 7日以上前の投稿からランダムに1件 -> ラベル「あの日の思い出」
5. 該当なし                        -> null（UIはカードごと非表示）
```

- 「ちょうど◯前」の日付算出は **`packages/date`** を使う
- 該当日に複数投稿がある場合は、画像のある投稿を優先する（無ければ最新）
- `readProcedure` の上に載せる（デモでも見える）
- 1日の間は同じ結果を返す（JST の日付をキーにする）。開くたびに変わると「思い出」にならない

### カードのデザイン
- 画像を大きく、その上または下にラベルと日付
- 本文を1〜2行だけ添える
- **タップの挙動**（当初「元の投稿へ遷移する」と書いていた。**変更した**）
  - **画像をタップ**したら全画面表示（017 の再利用）
  - **本文があれば、カードのタップで展開・折りたたみができる**
    （**省略が起きているかは判定しない。**判定するには文字の実レイアウトを測る必要があり、
    jsdom の結合テストで検証できない〈`conventions.md` 6節〉。
    省略されていない本文をタップしても何も起きないだけで、害が無い）
  - **投稿の詳細画面は作らない。**ホームに個別ルートが無く、
    この1箇所のために画面と手続きを増やす価値が無い（B の判断。妥当）

  ただし読み替えをそのままにすると穴が残る。`memory.get` は
  **「画像のある投稿を優先する。無ければ最新」**なので、
  **テキストのみの投稿が思い出しになりうる。**
  そのとき本文は1〜2行に省略され、**タップ先が無い。**
  「思い出を見返す」機能なのに、**見返せない。**

  展開で塞ぐ。ルートも手続きも増えない
- デザインサンプルの「去年の今日」画面を参考にする

## テストで証明すること
| 条件 | 期待 |
|---|---|
| 1ヶ月前に投稿がある | それが返り、ラベルが「1ヶ月前の今日」 |
| 1ヶ月前・半年前が無く1年前にある | 1年前が返る |
| どの節目にも無いが古い投稿はある | ランダムに1件返る |
| 投稿が7日分しかない | `null` が返る |
| 投稿ゼロ | `null` が返る |
| 1ヶ月前が月末（1/31 の1ヶ月前など） | 例外を出さず、決めた規則どおりに動く |

## 確認観点
- `null` のときにカードが消え、ホームのレイアウトが崩れないか
- **テキストのみの投稿が思い出しになったとき、本文を最後まで読めるか**
- 月末の日付計算で落ちないか
- 同じ日に何度開いても同じ投稿が出るか
