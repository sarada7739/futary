# 013: 思い出し

## 目的
過去の投稿を掘り起こしてホームに出す。
「時間が経つほど価値が増す」というこのアプリの核心にあたる機能。

## 実装内容

**日付は `packages/date` を使う。存在しない日はその月の末日に寄せる**
（`architecture.md` 5節）。3月31日の「1ヶ月前」は **2月28日**であり、
素の `Date` が返す 3月3日ではない。

**3月29日・30日・31日の「1ヶ月前」は3日とも2月28日になる。**
同じ投稿が3日続けて出ることがあるが**不具合ではない。**

**4段の探索すべてに `AND deleted_at IS NULL` を含める**（`architecture.md` 4節）。
忘れると**削除した投稿がホームの最上部に「思い出」として復活する。**
消したという操作が、最も目につく場所で裏切られる。


### 探索順（ADR-006 / `docs/architecture.md` 5節）
```
1. ちょうど1ヶ月前の投稿          -> ラベル「1ヶ月前の今日」
2. ちょうど半年前の投稿            -> ラベル「半年前の今日」
3. ちょうど1年前の投稿             -> ラベル「1年前の今日」
4. 7日以上前の投稿からランダムに1件 -> ラベル「あの日の思い出」
5. 該当なし                        -> null（UIはカードごと非表示）
```

- 「ちょうど◯前」の日付算出は **`packages/date`** を使う
- 該当日に複数投稿がある場合は、画像のある投稿を優先する（無ければ最新）
- `readProcedure` の上に載せる（デモでも見える）
- 1日の間は同じ結果を返す（JST の日付をキーにする）。開くたびに変わると「思い出」にならない

### カードのデザイン
- 画像を大きく、その上または下にラベルと日付
- 本文を1〜2行だけ添える
- **タップの挙動**（当初「元の投稿へ遷移する」と書いていた。**変更した**）
  - **画像をタップ**したら全画面表示（017 の再利用）
  - **本文が省略されているとき、カードのタップで展開する**
  - **投稿の詳細画面は作らない。**ホームに個別ルートが無く、
    この1箇所のために画面と手続きを増やす価値が無い（B の判断。妥当）

  ただし読み替えをそのままにすると穴が残る。`memory.get` は
  **「画像のある投稿を優先する。無ければ最新」**なので、
  **テキストのみの投稿が思い出しになりうる。**
  そのとき本文は1〜2行に省略され、**タップ先が無い。**
  「思い出を見返す」機能なのに、**見返せない。**

  展開で塞ぐ。ルートも手続きも増えない
- デザインサンプルの「去年の今日」画面を参考にする

## テストで証明すること
| 条件 | 期待 |
|---|---|
| 1ヶ月前に投稿がある | それが返り、ラベルが「1ヶ月前の今日」 |
| 1ヶ月前・半年前が無く1年前にある | 1年前が返る |
| どの節目にも無いが古い投稿はある | ランダムに1件返る |
| 投稿が7日分しかない | `null` が返る |
| 投稿ゼロ | `null` が返る |
| 1ヶ月前が月末（1/31 の1ヶ月前など） | 例外を出さず、決めた規則どおりに動く |

## 確認観点
- `null` のときにカードが消え、ホームのレイアウトが崩れないか
- **テキストのみの投稿が思い出しになったとき、本文を最後まで読めるか**
- 月末の日付計算で落ちないか
- 同じ日に何度開いても同じ投稿が出るか

## 実装メモ

- `packages/date`に`jstDayRangeMs(date)`を新設した。指定したJSTの暦日が
  覆うUnixミリ秒の範囲`[fromMs, toMs)`を返す。`posts.created_at`（Unix秒）を
  JSTの暦日で絞り込むSQLの範囲条件に使う（`toEpochDay(date) - JST_OFFSET_MS`
  で求まる。`todayJst`の逆演算にあたる）
- **4段の探索すべてに`AND deleted_at IS NULL`を含めた**（L69。Aが
  `architecture.md`4節に「`posts`を読むクエリには必ず`deleted_at IS NULL`を
  含める。例外なし」という規則を新設したのを受けて実装）
- 「ランダムに1件」と「1日の間は同じ結果」の両立: `(coupleId, JST日付)`を
  種にした決定的なハッシュ（`stableHash`。31を掛けて文字コードを足すだけの
  単純なもの）で候補のOFFSETを決める。`ORDER BY RANDOM()`は使わない。
  `ORDER BY`を`created_at, id`で明示的に固定した（Rの指摘: 種が決定的でも
  行の順序がSQLiteの裁量だと全体が決定的にならない）
- 7日境界は「ちょうど7日前を含む」に決めた（Rと合意）。境界の両側
  （7日前ぴったり→対象になる、6日前→対象にならない）をテストで固定した
- `stableHash`をexportし、決定性（同じ入力は同じ値）を純粋関数として直接
  テストした。procedureの`memory.get`自体は`todayJst()`を引数なしで呼ぶ
  設計のため（他のprocedureと同じ）、「日付が変わったら結果も変わりうる」を
  統合テストレベルでは検証できず、この制約をテストのコメントに明記した
- `apps/app/components/memory-card.tsx`: 「タップで元の投稿へ遷移する」は、
  ホーム画面（無限スクロールの`FlatList`のみ）に投稿ごとの個別ルートが
  存在しないため、既存パターン（017の`ImageViewer`）を再利用し画像の全画面
  表示に読み替えた。新しいルートは追加していない（タスク定義の「変更対象
  ファイル」に無いため）
- **本文タップで展開/折りたたみを追加**（Aがタスク定義に追記・PR #101。
  Rも同じ穴を独立に指摘）。画像を優先しない探索4段目（ランダム）ではテキスト
  のみの投稿が思い出しになりうり、画像タップという代替が無いテキストのみの
  思い出は読み返す手段自体が無かった。実際に省略（2行を超える）が起きているか
  どうかを判定せず、本文があれば常にタップで展開できる形にした（当たり判定の
  正確さに依存させない。conventions.md 6節と同じ考え方）。日をまたいで
  `memory.get`が別の投稿へ切り替わったときは展開状態をリセットする
- 該当なし（null）・読み込み中・通信エラーはすべてカード非表示（統計カードと
  違い補助的なコンテンツのため骨格表示は設けない）
- テストは apps/api 193件（新規15件。うち`memory.test.ts`13件・
  `stableHash`単体3件）・apps/app 62件（新規6件。本文展開のテストを含む）
  すべて緑。型チェック・lint通過
- 005の認可テストに`memory.get`を追加（NEEDS_ONBOARDING・デモペア読み取り）。
  基底経由チェックの実在数を17→18に更新
