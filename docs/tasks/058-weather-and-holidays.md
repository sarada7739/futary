# 058: カレンダーに天気と祝日を出す

## 目的

**人間の指示（2026-09-17）。月表示のカレンダーに、今日から 7 日先までの天気と、祝日を出す。**
天気は気象庁の予報（無料・鍵なし）。**位置情報は取らない。**利用者が地域を選ぶ。

- 絵: `docs/sample/weather/icons-source.png`（人間の絵。AI 生成。6 マス。**上段真ん中〈太陽 + 雲〉は使わない**）
- 祝日は内閣府の表を同梱し、外部の JSON で更新する（0節 #9。運用の手間をほぼ無くす）

## 0. 決めたこと（A）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 天気の出どころ | **気象庁の予報 JSON**（`https://www.jma.go.jp/bosai/forecast/data/forecast/{officeCode}.json`）。鍵なし。政府の公開データ（商用可） | Open-Meteo は非商用のみ。OpenWeatherMap は鍵の管理が増え、日本語の予報文が無い |
| 2 | 地域 | **個人ごとに 1 つ**（`couple_members.weather_area`。気象庁の予報区のコード。NULL = 未設定）。**GPS・IP からの推定はしない** | 位置情報を取らない（`/privacy`「位置情報を取得しません」を保つ）。都道府県程度の粒度は個人を特定しない |
| 3 | 地域の選び方 | マイページに「天気の地域」。**都道府県 → 予報区**の 2 段（多くの県は 1 つ。北海道・東京・鹿児島・沖縄などは複数）。表はコードに同梱（気象庁の `area.json` から B が作る。`class10`〈一次細分区域〉の粒度） | 選ぶだけ。API に一覧を取りに行かない |
| 4 | 月表示 | **自分の地域**の天気を、**今日から 7 日先まで**のマスに（絵 + 最高気温）。過去・8 日以降は出さない。地域が未設定なら何も出さない（マイページへの導線は 1 度だけ、月表示の上に「天気の地域を選ぶ ›」の細い帯。× で消せて、消したら端末に記憶〈`localStorage`。043 と同じ作法〉） | 予報しか無い。押し付けない |
| 5 | 予定の詳細 | 7 日以内の日なら（予定の有無によらず。予定が無い日は「この日の予定はありません」の下に）「天気」の行。**ふたりの地域が同じか、片方だけ設定なら 1 行**。違えば 2 行（「自分の地域名: …」「相手の地域名: …」）。地域名は予報区の名前 | 人間の指示。同じ地域を 2 回書かない |
| 6 | 絵 | 5 つ: **晴（上段左）・曇（上段右）・雨（下段左）・雪（下段中）・雷（下段右）**。`packages/ui/assets/weather-{sun,cloud,rain,snow,thunder}.png`（役割の名前。透過 PNG。表示は最大 28 CSS px なので **112px** に縮小） | 上段真ん中は使わない（人間の指示） |
| 7 | 重ね方 | 気象庁の**天気コード**（3 桁。100 晴・101 晴時々曇・200 曇・201 曇時々晴・300 雨・400 雪 … 約 100 個）を **主 + 副（0〜1 個）の絵**に対応づける表を `packages/ui` に持つ。主は 28px、副は右下に 16px で重ねる。「のち」も「時々」も同じ扱い（主 = 前半、副 = 後半）。雷は副に。表は気象庁の `Const/weather_code` の一覧から B が作り、**全コードを網羅**（テストで固定。無いコードは主 = 曇で倒す） | 「曇りのち晴れ」は雲の上に太陽を小さく |
| 8 | 取り方 | **Worker が気象庁から取る**（アプリのブラウザから直接取らない）。`weather.get {} -> 7 日分`。**予報区ごとに 1 時間キャッシュ**（Worker のメモリ。`billing.prices` と同じ作法）。失敗したら **`{ days: [] }`**（エラーにしない。天気が出ないだけ） | CSP を開けない。気象庁の JSON は正式な API ではなく形が変わりうる。吸収する場所を 1 つに |
| 9 | 祝日 | **内閣府の表を同梱**（`packages/date/holidays.ts`。今年〜来年。内閣府の `syukujitsu.csv` から B が作る）**+ Worker が `https://holidays-jp.github.io/api/v1/date.json` を 1 日 1 回取って上書き**（取れなければ同梱の表）。**同梱の表は内閣府が公表している年まで**（今は 2026・2027。内閣府の CSV は翌年分までしか無いので、先へは延ばせない）。内閣府が翌年分を公表したら（例年 2 月）`make-tables.mjs` で作り直す。`holiday.list { year } -> { [date]: name }` | 運用の手間をほぼ無くす。同梱の表は保険で、年 1 回の更新は「したほうがいい」であって「しないと止まる」ではない |
| 10 | 祝日の見せ方 | 月表示の日付を **`event-anniversary` と同じ赤**（日曜と同じ扱い）。名前は日付を押したときの一覧の一番上に「〇〇の日」の 1 行（予定ではないので押せない） | 色を増やさない |
| 11 | 外部の fetch の口 | `security-requirements.md` の「外部 URL の取得（040）」に**2 つ目の口**を足す: **固定の URL に、予報区のコード（数字 6 桁。表にあるものだけ）を差し込むだけ**。利用者の入力を URL に入れない。応答は Zod で形を検証し、要る項目だけ取り出す。12 秒で打ち切る | 040 と違い、行き先は運営が決めた 2 つの URL だけ |
| 12 | ゲスト（デモ） | 地域は **東京地方（130000）で固定**。ゆい・れんの両方 | デモでも天気が見える |
| 13 | プライバシーポリシー | 1 節に「天気を出すために選んだ地域（予報区。位置情報は取得しません）」の 1 行。3 節「誰に渡すか」に**気象庁・holidays-jp は渡さない**（Worker が公開データを取りに行くだけで、利用者の情報は送らない）と明記 | 取る情報が 1 つ増える。草案は A が直した。HTML は B |
| 14 | リリース履歴 | **3.3.0「カレンダーに天気と祝日」**（本文: 「マイページで地域を選ぶと、7 日先までの天気が出ます / 祝日が赤くなります」） | 利用者に見える |
| 15 | やらないこと | 過去の天気・8 日以降・降水確率・時間ごと・通知・ホームへの表示 | 増やしすぎない |

## 1. API

```
weather.get         {} -> { area: { code, name } | null, days: [{ date, code, tempMax: number|null, tempMin: number|null }] }
                    自分の地域（ctx.userId の weather_area）。未設定なら area null・days []。失敗も days []
                    7 日分（今日から。気象庁が返す範囲まで。気温が無い日は null）
weather.getForDate  { date } -> { mine: {...} | null, partner: {...} | null, same: boolean }（予定の詳細用。7 日の外は両方 null）
holiday.list        { year } -> { holidays: { [date: "YYYY-MM-DD"]: string } }
me.updateWeatherArea { areaCode: string | null } -> {}   // 表に無いコードは INVALID_INPUT
couple.get          weatherArea: { code, name } | null を足す（自分の分。相手の分は getForDate でだけ）
```

- `weather.*`・`holiday.*` は読み取り。ゲストも通る（デモは東京）
- `couple_members.weather_area TEXT`（NULL 可）。マイグレーション

## 2. 画面

- マイページ: 「天気の地域」の行 → 都道府県 → 予報区 の 2 段のシート。「設定しない」で NULL
- カレンダー月表示: 0節 #4・#10。天気の絵は日付の下、数字の上に被せない。マスが小さいので **絵 + 最高気温だけ**
- 予定の詳細: 0節 #5
- ピンク／ホワイト両方

## 3. テストで証明すること

| # | 何を | どこで |
|---|---|---|
| T1 | 天気コードの表: 気象庁の全コードに主の絵がある。「晴のち曇」→ 主 sun・副 cloud。「曇時々雨」→ 主 cloud・副 rain。雷を含むコード → 副 thunder。無いコード → 主 cloud | `packages/ui` |
| T2 | `weather.get`: 固定の応答（気象庁の JSON の写し）から 7 日分が出る。気象庁が落ちている（5xx・12 秒超・形が違う）→ `days: []` で 200。予報区ごとに 1 時間キャッシュ（2 回目は fetch しない） | `apps/api` |
| T3 | fetch する URL が固定の 2 つだけで、差し込まれるのは表にあるコードだけ（表に無いコードは `INVALID_INPUT` で fetch しない） | `apps/api` |
| T4 | `getForDate`: 同じ地域 → `same: true`。片方未設定 → その側 null。8 日先 → 両方 null | `apps/api` |
| T5 | `holiday.list`: 同梱の表で今年の祝日が出る。外部の JSON が取れれば上書き、取れなければ同梱のまま | `apps/api` |
| T6 | 別ペアの相手の地域を返さない（`couple_id` スコープ） | `apps/api` |
| T7 | 画面: 地域を選ぶ → 月表示に 7 日分の絵。未設定 → 出ない・帯が出る・× で消える。予定の詳細の 1 行／2 行。祝日の赤と名前 | `apps/app` |
| T8 | `/privacy` に地域の行がある | `apps/api` |
