# 043: リリース履歴

## 目的

**人間の指示。何が新しくなったかを、アプリの中で見られるようにする。**

- ホームの下に「リリース履歴を見る」のボタン。新しい項目があれば **NEW** のバッジ
- リリース履歴の画面: 新しい順に、日付・版・題名・箇条書き。新機能へ飛ぶリンク
- 新しい項目がある間、ホームを開いたときに**「新機能のお知らせ」のシート**を 1 度出す
- 絵は `docs/sample/simpleMode/リリース履歴/`（4 枚。人間の絵。**ホワイトの絵**。ピンクは既存の部品に任せる）

**細かい数字（余白・文字サイズ・バッジの位置・角丸）は B が決める**（人間の指示）。A は「何を・いつ・どこに」だけ決める。

## 0. 先に決めたこと（A）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | データはどこに持つか | **コードの中の配列**（`apps/app/lib/releases.ts`）。表も手続きも作らない | 書くのは私たちだけ。リリースのたびにコードが変わるので、同じ PR に 1 項目足せばいい。サーバを通す理由が無い |
| 2 | 「見た」をどこに持つか | **端末の `window.localStorage`**（鍵 1 つ: 最後に見た版）。サーバに持たない | お知らせであって状態ではない。端末が変われば出直してよい。ゲストにも効く |
| 3 | 版の番号 | **この一覧の中だけの番号。**`v1.0.0` = 016 の公開。機能を足すごとに **minor** を上げる（1.1.0, 1.2.0, …）。アルバムは **2.0.0**（人間の絵に合わせる） | アプリに版の概念は無かった。ここで初めて作る。`package.json` の version は触らない |
| 4 | 「後で通知する」 | **閉じるだけ。見たことにしない。**次にアプリを開いたとき（ページ読み込み）にまた出す。同じ起動の中では出し直さない（`sessionStorage`） | 「後で」を「二度と」にしない。ただしホームに戻るたびに出すのはうるさい |
| 5 | 「閉じる ×」・シートの外を押す | **見たことにする**（最新の版を保存） | 閉じたのに次も出るのは、押した意味が無い |
| 6 | 「使ってみる」 | 見たことにして、その機能の画面へ | 同上 + 導線 |
| 7 | リリース履歴の画面を開く | **見たことにする**（ホームのバッジも消える） | 一覧を開いた = 見た |
| 8 | 最新の項目の「NEW!」バッジ（画面の中） | **常に出す**（見た・見ないに関係なく、いちばん新しい項目に） | 「いちばん新しい」の印。未読の印はホームのボタンのバッジが持つ |
| 9 | ストレージが使えない（例外・プライベートモード） | **見たことにして扱う**（バッジもシートも出さない） | 毎回シートが出る方が害。一覧はボタンから開ける |
| 10 | 絵の「カラータグ」「予算や優先度」「Pinterest 風」 | **書かない**。存在しない機能を書かない | 文言は 3節。絵は見た目の参考 |

## 1. データ

```ts
// apps/app/lib/releases.ts
export type Release = {
  version: string;        // "2.0.0"
  date: string;           // "2026-09-14"（YYYY-MM-DD。JST）
  title: string;          // "アルバム機能を追加"
  items: string[];        // 箇条書き。1〜5 行。各 40 文字まで
  route?: string;         // "/album"。あれば「新機能を見る →」と、お知らせシートの「使ってみる」の行き先
  emoji?: string;         // 題名の末尾に付ける絵文字（初回リリースの 🎉 だけ）
};
export const RELEASES: readonly Release[] = [ /* 新しい順 */ ];
export const LATEST_VERSION = RELEASES[0].version;
```

- **新しい順に並べる。**先頭が最新。`LATEST_VERSION` は先頭から取る（2 箇所に持たない）
- **日付は B が git から取る**（そのタスクの実装 PR が `main` に入った日。`git log --first-parent --date=short`）。A が書いた下の表の日付は仮
- テストで固定: 新しい順（`date` 降順）・`version` が重複しない・`items` が 1〜5 行・`route` が既存の画面（`router` の型で弾けるなら型で）

## 2. 「見た」の持ち方

```
window.localStorage["futary.releaseSeen"] = "2.0.0"      // 最後に見た版
window.sessionStorage["futary.releaseLater"] = "2.0.0"   // この起動で「後で」を押した版
```

- `hasUnseenRelease()` = `releaseSeen !== LATEST_VERSION`（ストレージが例外なら **false**。0節 #9）
- `markReleaseSeen()` = `releaseSeen = LATEST_VERSION`
- **`window.localStorage` を使う**（Node 25 の global `localStorage` はメソッドの無い空オブジェクト。テストは `apps/app/test/setup.ts` の in-memory Storage）
- 版の比較は**文字列の一致だけ**（大小を比べない。旧い版を見た端末で新しい版が出れば「違う」で十分）

## 3. 画面

### ホームのボタン（絵 `01`・`03`）

3×3 のパネルの下、全幅の 1 本。左に ✨、中央に「リリース履歴を見る」、右に `›`。

- **未読（`hasUnseenRelease()`）なら右上に「NEW」のバッジ**（絵 `01` の 3 枚目）。読めば消える
- 押すと `/releases`
- ✨ は絵文字ではなく**線画の小さなアイコン**（ピンクの `panel-*.png` と同じ線）。B が描く。描けなければ `✦` の文字で仮に置いて結果に書く
- ピンクでもホワイトでも `Card`/`surface` の部品に任せる。色を直に書かない

### リリース履歴: `(tabs)/releases.tsx`（`href: null`。絵 `02`）

- ヘッダー: 題名「リリース履歴」。**左に ‹ 戻る**（`/` へ固定。041 詳細と同じ理由）。絵の右の × は置かない（戻るが 1 つあれば足りる。`(tabs)` の中なのでタブバーもある）
- 先頭の一文: 「これまでのアップデートをご紹介。」
- カード（新しい順）: 日付（`YYYY.MM.DD`）・版のチップ（`v2.0.0`）・題名・箇条書き（先頭に小さな点）。
  **`route` があれば「新機能を見る →」**（押すとその画面）。**最新の 1 枚だけ枠を `primary` にして「NEW!」のバッジ**（0節 #8）
- 開いた時点で `markReleaseSeen()`（0節 #7）
- 8 項目で固定長。スクロールするだけ。ページングは無い

### 新機能のお知らせ（シート。絵 `04`）

**ホームを開いたとき**、`hasUnseenRelease()` かつ `releaseLater !== LATEST_VERSION` なら出す。**最新の 1 項目だけ**（複数を溜めない。飛ばした版は一覧で読める）。

- 上に贈り物の絵（絵 `04`。**B が `docs/sample/` にある絵を切り出すか、`packages/ui` の既存の線画で代える**。凝らない）と「NEW」
- 題名「新機能のお知らせ」、副題「もっと便利に、もっと楽しく。」
- カード: 機能の絵（ホームのそのパネルの写真タイル `panel-white-*.jpg` を流用。**新しい絵を作らない**）・`title`・`items` の先頭 2 行・**「使ってみる ›」**（`route` があるときだけ。無ければカードにボタン無し）
- 下に「後で通知する」（0節 #4）・「閉じる ×」（0節 #5）
- 部品は 041 で出した `components/sheet.tsx`（ほしいもの・アルバムと同じ）
- **ゲストにも出す**（デモで最初に触る画面で、新しいものが見えるのは良い）。「使ってみる」の先がゲストで書けない画面でも見られる
- **オンボーディング（ペアが無い）では出さない**。ホーム = `(tabs)/index.tsx` に限る

### ピンクの見え方

絵はホワイト。**画面ファイルで `appearance` を読まない**（039）。既存の部品と `useTheme().colors` に任せる。両モードのスクリーンショットを証跡に。

## 4. リリースのたびにやること（規約に足す）

**機能を足すタスクの完了条件に「`releases.ts` に 1 項目足す」を含める。**文言は A がタスク定義に書く（このタスクの 1節の表と同じ形）。
`conventions.md` 8節（動作証跡）の近くに 1 行足す（A がこの起票と同じ PR で）。

## 5. やらないもの

| | 扱い |
|---|---|
| サーバの表・手続き | しない（0節 #1） |
| 「見た」の同期（端末をまたぐ） | しない（0節 #2） |
| プッシュ通知・「後で通知する」の実際の通知 | しない（`requirements.md` 5節。「後で」= 次の起動で出し直す） |
| 複数の未読をまとめて出す | しない。最新だけ。残りは一覧 |
| `package.json` の version との連動 | しない（0節 #3） |
| 存在しない機能の文言（カラータグ等） | 書かない（0節 #10） |

## 6. テストで証明すること

| # | 何を | どこで |

| T1 | `RELEASES`: 新しい順・`version` 重複なし・`items` 1〜5 行・`LATEST_VERSION` が先頭 | `apps/app` |

| T6 | オンボーディング画面ではシートが出ない | `apps/app` |

## 確認観点

- 初めて開くとシートが出て、「閉じる」で消え、次に開いても出ない
- 「後で」→ ホームに戻っても出ない → アプリを開き直すと出る
- ホームのボタンの NEW が、一覧を開くと消える
- ピンク・ホワイトの両方で崩れない（iPhone 幅・PC 幅）

- `artifacts/043/` にスクリーンショット（両モード × ホームのボタン（NEW あり／なし）・一覧・シート）

## 停止条件

- `sessionStorage` が Expo Web で使えない → `localStorage` に起動 ID を持たせる等、B が代替して結果に書く。A の手番は要らない
- 贈り物の絵が作れない → 絵無しで NEW のバッジだけにして結果に書く
- それ以外で仕様の判断が要る → `state.md` に書いて A へ
