# 035: 見た目を作り込む

## 目的

**人間がモックアップ2枚（ホーム・サインイン）を出した。「可能な範囲で」寄せる。**

**完全一致は目標ではない。**寄せられるところを寄せ、**寄せないと決めたものを結果に書く**
（`conventions.md` 6節「検証の範囲から外したものは、結果に書く」）。

## 0. モックアップの置き場所

**`docs/sample/mockup/` に人間が置く。**（起票時点で未配置。**人間へ依頼済み**）

- `home.jpg` — ホーム画面
- `signin.jpg` — サインイン画面

**置かれるまで着手しない。**下の記述は A が画面を見て書いたものだが、
**文章はモックの代わりにならない。**

## 1. 入れる依存は1つだけ

**`expo-linear-gradient`。**Expo 標準パッケージで、Web でも動く。

**それ以外は入れない。**

| | |
|---|---|
| `expo-blur` | **入れない。**Web での挙動が読めない。ボケは画像で足りる |
| マスク系（文字にグラデをかけるもの） | **入れない。**下記3節 |
| `react-native-gesture-handler` / `reanimated` | **入れない**（`requirements.md` 5節のまま） |

## 2. ホーム

### デモバナー
- **ピル型。**淡いグラデーションの地。左にアイコン、右端に「ログイン」
- いまの形に近い。**寄せるのは角丸と地の淡さ**

### 記念日カード（`stats-card.tsx`）— ここが主役
- **淡いグラデーションの地**（`expo-linear-gradient`）
- **アバターは円形＋光るリング。**枠と `shadow` で作る
- 2人の間に**ハート**
- **「付き合って」→ 大きな数字 → 「日目」**の三段。数字が主役
- 下に**「会った日数：94日」をピルで**

### 背景の光のボケ
- **コードで作らない。画像を1枚敷く**
- **`docs/sample/透過素材/` に既にキラキラがある**（`6sj6V6ve.png`）。**新しく作らない**
- 敷けないなら敷かない。**無くても他が効く**

### 機能パネル（`feature-panel.tsx`）— 020 の判断を覆す
- **白いカード**（`surface` 地 + `radius` + `shadow.card`）にする
- **「COMING SOON」を薄く重ねる**

**020 で「枠線も背景も持たない」と決めた。**理由は
**「薄い枠は『押せそうな箱』に見える」**だった。

**モックは枠線ではない。白い面と影である。**
**020 が嫌ったものと別物なので、判断を覆す。**

**押せる／押せないの差を濃さで見せる、という 020 の考え方は残す。**

### 「次フェーズ」→「COMING SOON」
- **「次フェーズ」は開発の都合の言葉である。利用者の言葉ではない**
- **これは字種の趣味ではなく、文言の質の話である**

### ボトムタブ
- **浮かせる。**画面下端に貼り付けず、左右と下に余白を取ったピル型にする
- 中央の **＋ は大きな丸**（いまの FAB を活かす）。**光彩を足す**
- **ラベルは日本語のまま。**モックは英字だが、**`requirements.md` 6節「言語: 日本語のみ」を、
  見た目のために変えない。**アイコンと短い日本語で既に読める

**浮かせると、下のコンテンツが隠れる。**
**各画面のスクロールの下パディングを、タブバーの高さ＋余白ぶん足すこと。**
**「隠れていないか」を全画面で見ること。**

## 3. 寄せないもの（先に決める）

| モックの要素 | 扱い |
|---|---|
| **数字のグラデーション文字** | **やらない。**マスク系のライブラリが要る。**単色（`brand-ink`）で足りる。**大きさと字面で効く |
| **タブラベルの英字化** | **やらない**（上記） |
| 細かいピクセル一致 | **目指さない。**トークンの範囲で寄せる |

**「できない」ではなく「やらないと決めた」である。**理由を結果に書くこと。

## 4. サインイン画面

- 中央に**大きなロゴ**
- **タグライン2行**（「大切な人と、ずっとつながるための / ふたり専用SNS」）
- ボタン3つ。**既存のバリアントで足りる。新しいバリアントを作らない**

| モック | 使うもの |
|---|---|
| 「ログイン」塗りつぶし | `primary` |
| 「新しくはじめる」白地＋枠 | `secondary` |
| 「ゲストではじめる」 | `ghost` |

**バリアントを増やさない。**増やすと、次に「どれを使うか」で迷う。

## 5. `packages/ui` の規則は変えない

**`packages/ui` のコンポーネントは `style` を受け取らない**（`architecture.md` 7節）。

**必要ならコンポーネント側にプロパティを足す。**呼ぶ側から `style` を渡す形にしない。

**新しく足したトークンは `architecture.md` 7節に書く。**書くのは A。
**B は「足したいトークン」を挙げて A に上げる。**

## テストで証明すること
- **既存のテストが全部緑のまま**（見た目の変更でロジックを壊していない）
- **押せないパネルが押せないまま**（`onPress` の有無で分かれる構造を変えていない）
- **浮かせたタブバーで、各画面の一番下の要素が隠れていない**

## 確認観点
- **モックと並べて、どこが寄って、どこが寄っていないか**
- **押せるものと押せないものの差が、いまより分かりにくくなっていないか**
- **タブバーに隠れるものが無いか**（全画面）
- **スマホ幅とPC幅の両方**
