# 026: 実機確認の一本化

## 目的

**人間が本番に1回だけ触って、溜まった未消化の実機確認をすべて消化できる状態を作る。**

人間の指示（「実機確認はまとめてあとでしたい」）。
**まとめる側の準備ができていないと、「あとで」は来ない。**

いま未消化の項目は `artifacts/014/` `016/` `022/` `023/` `024/` `025/` と
`fix-*/` に散っている。**人間は21個のファイルを開かない。**

## 1. 未消化の項目の置き場所を1つにする

**`docs/manual-check.md` を新設する。未消化の実機確認項目は、ここにしかない。**

`docs/state.md` と同じ考え方である。**探す場所が1つでないものは、探されない。**

| | |
|---|---|
| `artifacts/NNN/manual-check.md` | **そのタスクの時点の記録。**残す。書き換えない |
| **`docs/manual-check.md`** | **いま未消化なものの唯一の一覧** |

- 消化されたら **`docs/manual-check.md` から消す**。結果は `worklog.md` に書く
- **`artifacts/NNN/` 側は消さない。**当時何を頼んだかの記録である

## 2. 未消化かどうかを、根拠を出して判定する

**推測で消さない。**

- **判定の根拠は `docs/worklog.md` の記録である**
- **記録が無いものは未消化として扱う**。「たぶんやった」で落とさない
- 021 は 2026-08-31 に消化済み（worklog に記録がある）。**これが「消化済み」の形である**

**各項目に、どのタスク由来かの出典を残す**（`artifacts/022/manual-check.md` の何番、など）。
**一本化して出典が消えると、後から何を確かめた項目なのか読めなくなる。**

## 3. タスク番号順に並べない。動線の順に並べる

**人間は画面を触る。番号を触らない。**

**並べ替えるだけでは足りない。順序に依存があるものを明示する。**

### 分かっている依存（A の判断）

- **024（アカウント削除）は最後に置く。**先にやると、他の確認対象のデータが消える
- **025（招待コードの再発行）は、ペアが1人のときにしか導線が出ない。**
  いま本番のペアが2人揃っているなら、**この項目は 024 のあと、
  作り直しの途中でしか通れない**
- **016 の通し**（ログイン → ペア作成 → 招待 → 投稿 → リアクション → イベント →
  統計・思い出 → ログアウト）**も、その作り直しの流れと重なる**

**この3つは同じ1回の流れの中に並ぶ。**別々の項目として3回やらせない。

**いまの本番のペアが何人かは、B が確かめてから並べる**（`couple.get` でよい。
**「2人だろう」で書かない**）。

## 4. iPhone Safari が要るものだけを別の束にする

**幅は Chrome で足りる。エンジンの違いに依存するものだけが iPhone である**
（`conventions.md` 8節）。

- 022 のホイールピッカー（`scrollend` が Safari に無い件）は**ここ**
- **人間が Windows しか持っていない**ことを前提に、
  「PC の Safari で」と書かれた項目が残っていたら**そこで直す**

## 5. 本番のスクリーンショット（016 の残り）

**016 の完了条件で唯一残っている、人間を待たない項目である。**

- **未認証のデモ経路は B が撮れる。**撮って `artifacts/016/` に画像として保存する
- **ログイン後の画面は人間しか出せない。**`docs/manual-check.md` 側に入れる
- スマホ幅と PC 幅の両方
- **撮れなかったら、撮れなかったと書く。**そのとき
  **「できない」ではなく「いつならできるか」を書く**（`conventions.md` 8節）

## 書かないこと

既存の規約の再掲。**確認依頼書でいちばん壊れやすいところである。**

- **選択肢を書かない。**「気になるようなら◯◯で直せます」を書かない（`conventions.md` 8節）
- **人間に頼むのは「起きたか」「どのくらい気づくか」まで。**どう直すかは A が決める
- **B が項目に印を付けない。**印を付けるのは見た人間である

## 確認観点
- **`docs/manual-check.md` だけを開いて、上から順に触れるか**
- 各項目に**出典**があるか
- 順序の依存が**書かれているか**（並んでいるだけではなく）
- 未消化と判定した**根拠**が書かれているか
- iPhone が要るものと、要らないものが**分かれているか**
