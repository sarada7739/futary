# 052: プライバシーポリシーと利用規約のページ

## 目的

**人間の指示。プライバシーポリシーと利用規約を、ランディングのページとして公開する。**

- Google の OAuth 同意画面にプライバシーポリシーの URL が要る（無いと「確認されていないアプリ」の警告が続く）
- iOS を出すときも App Store に URL が要る
- 特定商取引法の表記は**まだ**（売り始めるとき。048 段階2）

## 0. 決めたこと（A）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 文面 | `docs/legal/privacy-policy-draft.md`・`docs/legal/terms-draft.md`（A の草案）。**空欄は人間が埋めてから B が写す**。B は文面を変えない | 文面は人間のもの |
| 2 | 置き場 | `apps/landing/privacy.html`・`apps/landing/terms.html`（静的 HTML）。URL は `/privacy`・`/terms` | ランディングと同じ仕組み。アプリの中に持たない（ログイン無しで読める必要がある） |
| 3 | 見た目 | ランディングの `style.css` を使う。見出し・段落・表だけ。**新しい CSS を書かない** | 読めればいい |

## 1. 人間の手番（先）

草案の空欄を埋める: 運営者名（氏名か屋号）・連絡先メール・年齢（13 か 16）・ログの保持日数・制定日・裁判所の地（利用規約 10 節）・AI 事業者の正式名と「学習に使われうる」の一文を残すか（`ai.ts` のデータ共有設定に合わせる）。
埋めたら `docs/legal/` の草案を直接直して A に言う（docs は人間も書ける）。

## 2. B の作業

- `privacy.html`・`terms.html`（草案を HTML に。`<title>`・`description`・`canonical` 相当の `<link>` は無くてよい。`noindex` にしない）
- フッター・マイページ・サインインのリンク（4）
- `build-public.mjs`（5）
- CSP は `index.html` と同じ扱いで通ること（inline script は無い）

## 3. テストで証明すること

| # | 何を | どこで |

| T1 | 公開ディレクトリに `/privacy` `/terms` があり、`GET` で 200 と HTML が返る（既存のランディングの検査と同じ形） | `apps/api` |
| T2 | 2 ページに「【」が残っていない（空欄の埋め忘れ） | 目視 + grep（結果に書く） |
| T3 | マイページ・サインイン画面にリンクがあり、押すと `/privacy` `/terms` を開く | `apps/app` |

## 完了条件

- T1〜T3。`pnpm -r test`・型チェック・lint
- デプロイ後、人間が **Google の OAuth 同意画面に `https://…/privacy` を登録**する（アプリのホームページの URL も）
- 人間が **OpenAI のダッシュボードでデータ共有（入力・出力の共有）をオフ**にする（ポリシー 3 節「学習には使われません」の実体。`ai.ts` のコメントも B が合わせる）
- `state.md` / `worklog.md`

## 停止条件
