# 042: 選んだ写真をまとめて写真ライブラリに保存する

## 目的

**人間の要望（041 段階1 の iPhone 実機、2026-09-14）。アルバムで選んだ写真を、まとめて iPhone の写真ライブラリに入れたい。**

- ZIP ではない。**ZIP は「ファイル」アプリに落ちるだけで、写真ライブラリに入らない**（要望に合わない）
- 041 段階2（1 枚を共有シートで保存）と**同じ経路に複数の `File` を渡す**。共有シートの「画像を保存」で、選んだ枚数がまとめて写真に入る

## 0. 方式（A が先に決めた）

| | |
|---|---|
| 経路 | 選んだ写真の署名付き URL を順に `fetch` → `Blob` → `File`（`filename`・`image/jpeg`）→ `navigator.share({ files })` |
| どこで | 詳細の**選択モード**に「保存」を足す。**タイムラインの詳細にも選択モードを足す**（「保存」だけ。削除・カバーは無い） |
| 出す条件 | `navigator.canShare({ files })` が真のときだけ「保存」を出す。**PC には出さない**（写真ライブラリが無い。1 枚ずつは今のまま） |
| 前提 | 本番 R2 の CORS に GET とアプリのオリジン（**確認済み**。2026-09-14 人間の `r2:cors:list`） |
| ライブラリ | **足さない**（ZIP を落としたので `fflate` も要らない） |

## 1. 上限

**1 回の共有は 20 枚まで。上限は「保存」に掛ける。選択には掛けない。**
選択モードは削除・カバーと共用で、選ぶ時点では何をするか分からない。21 枚以上選んでいるときは**「保存」を押せなくして**
「一度に保存できるのは 20 枚までです」の 1 行を出す（削除は今までどおり何枚でも。100 枚ずつ送る仕組みが既にある）。

- 根拠: 1600px の JPEG は 1 枚 300〜600KB。20 枚で 6〜12MB。共有シートに渡す `File` はブラウザのメモリに乗る。**iOS の共有シートが複数ファイルで何枚まで安定するかは A は知らない**（段階0で実測）。安定するなら 50 まで上げてよい（数だけ変える。A の手番は要らない）
- 「すべて選択」は置かない（上限があるので、選ぶのは利用者）

## 2. 段階0（人間の iPhone。本番で。結果を `artifacts/042/spike.md` に）

**測れるのは人間の iPhone だけなので、20 枚の上限で実装してデプロイしてから測る**（041 段階2 と同じ順）。B は実装のあと、人間に次を頼む:

1. 5 枚を選んで「保存」→ 共有シートの「画像を保存」で 5 枚が写真に入る
2. 20 枚を選んで同じ（**20 枚の `fetch` は 1 枚より長い**ので、041 段階2 で通っても落ちうる）。
   2 択で聞く: **共有シートが出る／出ずに（または途中で）止まる**。止まるなら: 「保存」を押した時点で `fetch` を始め、**全部揃ったら「写真に保存」のボタンを出して、そのタップで `share` を呼ぶ**（2 タップになるが、ユーザー操作の直後に `share` が来る）
3. 2 が通ったら、次の PR で上限を 50 にして同じことを聞く（通れば 50 のまま。落ちたら 20 に戻す）

## 3. 画面

- 選択モードの下のバーに「保存（N 枚）」。押すと進捗「3 / 12 枚を取得中…」→ 共有シート
- 共有シートを閉じた（`AbortError`）ときは何もしない（選択は残す）
- 1 枚でも `fetch` に失敗したら **その枚を飛ばして共有シートを出し、閉じたあとに「2 枚は取得できませんでした」**（全部やり直しにしない）
- ゲストも押せる（041 の保存と同じ理由）
- **`photo.downloadUrl` を枚数ぶん呼ぶ**（1 リクエスト 1 署名。20 回。専用の手続きを足さない。50 に上げるなら `photo.downloadUrls`（複数）を足すかを A が決める）

## 4. やらないもの

| | 扱い |
|---|---|
| ZIP | **しない**（写真ライブラリに入らない） |
| PC でのまとめて保存 | **しない**（1 枚ずつ）。要るなら次 |
| 20 枚超を 1 回で | しない（1節） |
| アルバム全体を 1 タップで | しない。選ぶのは利用者（上限があるため） |
