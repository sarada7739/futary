# 020: ホームの再構成

## 目的
ホームを**タイムラインを流す画面**から、**ふたりの状態を見て各機能へ入る画面**に変える。

人間が M3 の受け入れ確認中にモックアップ付きで出した要望。

- ホーム上部の「付き合って〇日目」は残す
- **タイムラインはホームから外し、独立したページにする**
- 代わりに**各機能へ入るパネル**を並べる
- タイムラインへは、ホームのパネルか**下部の「検索」の位置**から行く

## 019 のあとに行う

ホーム上部の表示は 019 の `primary_date`（付き合って / 結婚して / 非表示）に従う。
**019 が先に入っていないと、作り直しになる。**

## 変更対象ファイル
- `apps/app/app/(tabs)/index.tsx` — ホーム
- （新規）`apps/app/app/(tabs)/timeline.tsx` — タイムライン
- `apps/app/app/(tabs)/_layout.tsx` — タブの差し替え
- 削除: `apps/app/app/(tabs)/search.tsx`
- （新規）`apps/app/components/feature-panel.tsx`

## 1. タブから「準備中」が消える

**`検索` を `タイムライン` に置き換える。**

| 変更前 | 変更後 |
|---|---|
| ホーム / カレンダー / ＋投稿 / **検索**（準備中） / マイページ | ホーム / カレンダー / ＋投稿 / **タイムライン** / マイページ |

**これで「準備中です」のタブがゼロになる**（L71 が解消する）。
`検索` は `requirements.md` 5節のとおりスコープ外のままで、
**タブの枠も持たない。**

カレンダーはタブに残す（人間の指示）。**ホームのパネルからも行ける。**
入口が2つあるのは重複ではなく、**よく使うものへの近道である。**

## 2. ホームの構成

上から順に。

1. **ふたりのアバターと名前**（019 で変更できるようになったもの）
2. **記念日カード** — `primary_date` に従って「付き合って〇日目」/「結婚して〇日目」/
   **非表示**。会った日数もここに出す

   **`hidden` のとき、消すのは記念日の行だけ。会った日数は残す**（下記）
3. **機能パネル**

**思い出しカードと統計カードはホームから外し、それぞれのパネルの先へ移す。**
ホームは**状態を見て入口を選ぶ画面**にする。

## 3. パネル

モックアップの7枚に**タイムライン**を足した**8枚**を置く。**未実装のものも置く。**

### モックアップとの差はここ1枚だけ。人間に先に伝える

**モックアップにタイムラインのパネルは無い。**A が足した。ずれているのは
**動く側**であって、スコープ外の4枚は一致している（R が数えて確認）。

足す理由は3つ。

1. **人間の指示は「ホーム画面**または**下部の『検索』の位置から」だった。**
   どちらか一方でよいと読めるので、**両方あっても要望に反しない**
2. **カレンダーが既にタブとパネルの両方から行ける。**
   タイムラインだけ扱いが違うと不整合になる
3. モックアップのグリッドは 4+3 で**1枠空く。**8枚なら 4+4 で埋まる

**判断の是非より、黙って変えないことの方が重い。**
020 の受け入れは**人間が自分の絵と見比べる形**になる。
**枚数が違えば必ず気づく。**気づかれてから説明するのではなく、**先に伝える。**

**7枚に戻すなら、タブからだけ行く形になる。**それも要望を満たす。

| パネル | 行き先 |
|---|---|
| **タイムライン** | 新しい独立ページ |
| **カレンダー** | 既存 |
| **思い出** | 013 のカードを移した新しいページ |
| **統計** | 012 のカードを移した新しいページ |
| 今日どうだった？ | **次フェーズ** |
| リスト | **次フェーズ** |
| 気分の記録 | **次フェーズ** |
| AIまとめ | **次フェーズ** |

### 未実装のパネルは「次フェーズ」と分かる形で出す

**消さない。**`検索` タブについて決めたのと同じ判断である
（`state.md` L71。**作っていないことを隠すより、何を作る予定かを見せる方が
読み手に効く**）。**同じ問いに2つの答えを持たせない**（R の指摘）。

- 薄く表示し、**「次フェーズ」と読める形にする**
- **押しても何も起きない、にしない。**押せないことが見て分かるか、
  押したら「次フェーズで作ります」と伝わるか、どちらかにする
- **「準備中です」という文言は使わない。**
  作りかけに見える。**作らないと決めた、ではなく、次に作ると決めた**である

### 動くパネルの行き先

**思い出と統計は、いまホームにあるカードをそのまま移す。**新しく作らない。

- 統計のページには**4つ**を出す（付き合って〇日目・会った日数・投稿数・写真の枚数）。
  ホームの記念日カードは**そのうち2つの要約**である
- **`hidden` のときは3つになる。**`stats.get` が `days` を返さないため
  （019 の設計。**非表示にしたはずの数字を応答に乗せない**）。
  **「4つ全部」と書いていたのは誤りだった**（R の指摘）。
  隠すと決めたものは、統計ページでも隠れる
- 思い出のページには 013 のカードを出す

パネルが並ぶことで、**このプロダクトが何を目指しているかが一目で伝わる。**
動く4枚と次フェーズ4枚が並ぶ形は、**作った範囲と構想の両方**を見せる。

## 状態の網羅

| 状態 | 表示 |
|---|---|
| `primary_date = 'none'` | **記念日の行だけ消す。会った日数は残す**（下記）。パネルは出す |
| ペアが1人だけ | アバターの片方を「招待中」に |
| 統計の取得に失敗 | 記念日カードだけ落とす。**パネルは出す** |

### `hidden` で消すのは、言われたものだけ

人間の要望は「**付き合って〇日目**か**結婚して〇日目**か表示を選択できるように。
恥ずかしい人は**非表示**にもできるように」だった。

**恥ずかしいと言われたのは交際日数の方である。会った日数を隠す指示は無い。**

当初この表は「記念日カードごと非表示」と書いていた。**言われていないものまで消していた**
（R の指摘）。

**サーバは既に判断している。**`stats.get` は `hidden` のときも `meetupDays` を返す。
`days` だけを落としている（019）。**それなのに画面がカードごと消すと、
サーバの判断と画面の判断が食い違う。**

- **記念日の行だけ消す。会った日数は残す**
- `meetupDays` も隠したいという要望が出たら、そのとき 019 の契約を変える。
  **先回りして隠さない**

**行が1つだけ残る。**カードの高さが変わることを前提に組む。
**空白で埋めない。**確認観点の「上が間延びしないか」はこの形で見る。

**パネルは常に出す。**ホームの役割が「入口」である以上、
データの取得に失敗しても**入口が消えてはいけない。**

## 確認観点
- スマホ幅とPC幅の両方でパネルが破綻しないか（`layout.maxWidth = 640`）
- 未実装のパネルが**押せると誤解されないか**
- 記念日カードを非表示にしたとき、**上が間延びしないか**（行が1つ残る形で）
- **統計ページが `hidden` のとき3つになることが、欠落に見えないか**
- タイムラインのタブとホームのパネル、**どちらから入っても同じ画面か**
- 生の16進カラーが混入していないか
