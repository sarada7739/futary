# 016: 仕上げと公開

## 目的
本番環境で動かし、公開する。ここまでのタスクで積み残した粗を取る。

## 変更対象ファイル
- 各画面 — エラー処理・空状態・ローディングの見直し
- （新規）`README.md` — セットアップ手順、技術構成、設計判断へのリンク
- `.github/workflows/` — デプロイワークフロー、gitleaks、`pnpm audit`
- （新規）`docs/security-report.md` — 全体監査の結果

## 実装内容

### 仕上げ
- 全画面の「読み込み中 / 空 / エラー」の3状態を通しで確認し、欠けを埋める
- エラーメッセージを日本語で統一する。スタックトレース・SQL・内部パスを出さない
- サーバ内部エラーに一意のIDを振り、クライアントにはIDのみ返す
- 初回起動（ペア未作成）から投稿までの導線を通しで触り、詰まる箇所を直す

### CI / CD
- `main` へのマージで Cloudflare へデプロイする
- **deploy の前に `db:migrate:remote` を実行する。**ローカルのエミュレータと
  リモートの D1 は別物で、`db:migrate:local` だけでは本番に反映されない
  （L34 で実際にログインが全滅した。`architecture.md` 6節）
- **R2 バケットの CORS に本番オリジンを追加する。**忘れると画像アップロード
  だけが本番で失敗する（`architecture.md` 6節）
- ~~CI に gitleaks と `pnpm audit` を追加する。Dependabot を有効化する~~
  → **L11 として前倒しで実施済み**（`fix/ci-security-checks`）。016 では
  以下の**再評価**だけを行う

### README
- セットアップ手順（`pnpm install` から起動まで）
- 技術構成と、その選定理由へのリンク（`docs/decisions.md`）
- **開発体制の説明**（`docs/harness.md`）— Claude Code の複数セッションによる
  Maker-Checker 分離。これ自体が転職アピールの材料になる
- 公開URLとデモへのリンク

### 全体セキュリティ監査
1. `pnpm audit` と gitleaks を実行する
   - **`pnpm audit` は全重大度で実行する。** CI のゲートは high 以上だが、
     ここでは moderate 以下も人間が読む
   - **`pnpm.auditConfig.ignoreGhsas` の全項目を1件ずつ再評価する。**
     修正版が出ていれば消して依存を上げる。到達可能性の評価が今も正しいかを見る。
     **1件も残さずに済むならそれが最善**（`security-requirements.md` 9節。根本原因は L39）
   - **gitleaks は履歴全体に対して1度走らせる。** CI は差分しか見ておらず、
     検査を導入する前に混入したものを見つけられない。
     Public に切り替えた時点で履歴は全て読まれる
2. **その出力を security-auditor に読ませる**
3. 結果を `docs/security-report.md` に追記する
4. `docs/security-requirements.md` 9節の脅威 T1〜T8 について、
   それぞれ対策が実装されていることを1件ずつ確認する

**UI の視覚的な検証はここが初めてになる画面がある。**
M2（008 タイムライン・009 リアクション）は、**R が視覚的な結果を一度も見ないまま
締めた**（`conventions.md` 8節でタスク単位のスクリーンショットを撤回したため。
`state.md` L38・L58）。人間の実機操作では動作を確認しているが、
**独立した目でレイアウトを見る工程は通っていない。**

したがって 016 のスクリーンショット撮影は、証跡であると同時に
**初回の視覚レビューでもある。**撮って終わりにせず、撮った画像を見て
レイアウトの崩れ・色の逸脱を確認する。

### E2E 通し
以下の1本を通す。
```
デモを開く → 閲覧できることを確認 → 書き込みが拒否されることを確認
→ ログイン → ペア作成 → 招待コード発行 → 投稿 → リアクション
→ イベント登録 → 統計と思い出しの表示確認 → ログアウト
```

## 確認観点
- 本番環境で実際に動くか（ローカルでしか動かない設定が残っていないか）
- 秘密情報がリポジトリに含まれていないか（gitleaks が緑か）
- T1〜T8 の全てについて対策の所在を示せるか
- README の手順どおりに、まっさらな環境からセットアップできるか
