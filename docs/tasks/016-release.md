## 実装内容

### 仕上げ
- 全画面の「読み込み中 / 空 / エラー」の3状態を通しで確認し、欠けを埋める
- エラーメッセージを日本語で統一する。スタックトレース・SQL・内部パスを出さない

- 初回起動（ペア未作成）から投稿までの導線を通しで触り、詰まる箇所を直す

### CI / CD
- `main` へのマージで Cloudflare へデプロイする
- **deploy の前に `db:migrate:remote` を実行する。**ローカルのエミュレータと
  リモートの D1 は別物で、`db:migrate:local` だけでは本番に反映されない
  （L34 で実際にログインが全滅した。`architecture.md` 6節）
- **R2 バケットの CORS に本番オリジンを追加する。**忘れると画像アップロード
  だけが本番で失敗する（`architecture.md` 6節）
- **デモペアのシードを本番の D1 と R2 へ投入する。**014 はローカルまでで完了しており、
  **本番にデモデータが入るのはここが初めて**である。
  投入後、`DEMO_COUPLE_ID` を本番の値に設定する。
  **設定した ID が `is_demo = 1` の行を指していることを確認する**
  （`security-requirements.md` 3節の項目6。誤ると未認証の閲覧者に実ペアのデータが出る）

1. `pnpm audit` と gitleaks を実行する
   - **`pnpm audit` は全重大度で実行する。** CI のゲートは high 以上だが、
     ここでは moderate 以下も人間が読む
   - **`pnpm.auditConfig.ignoreGhsas` の全項目を1件ずつ再評価する。**
     修正版が出ていれば消して依存を上げる。到達可能性の評価が今も正しいかを見る。
     **1件も残さずに済むならそれが最善**（`security-requirements.md` 9節。根本原因は L39）
   - **gitleaks は履歴全体に対して1度走らせる。** CI は差分しか見ておらず、
     検査を導入する前に混入したものを見つけられない。
     Public に切り替えた時点で履歴は全て読まれる
2. **その出力を security-auditor に読ませる**
3. 結果を `docs/security-report.md` に追記する
4. `docs/security-requirements.md` 9節の脅威 T1〜T8 について、
   それぞれ対策が実装されていることを1件ずつ確認する

### E2E 通し

**当初この1本を「E2E テスト」として書いていたが、`conventions.md` 6節と食い違っていた。**

> **認証を伴う導線（ログイン → 投稿 → リアクション）を Playwright で自動化しない。**
> Google OAuth の自動化は実アカウントかモック IdP を要し、得られる保証に対して重い。

**自動化できないものを「テストが緑」の完了条件に置いていた。**2つに割る。

**(a) 自動テスト（デプロイ前に書ける）**

```
デモを開く → 閲覧できる → 書き込みが拒否される
```

**`conventions.md` 6節の「未認証のデモ閲覧経路のみ」がこれである。**

**(b) 人間の通し（デプロイ後）**

```
ログイン → ペア作成 → 招待コード発行 → 投稿 → リアクション
→ イベント登録 → 統計と思い出しの表示確認 → ログアウト
```

**これはテストではなく、人間の受け入れである。**
`artifacts/016/` に記録するのは**結果**であって、緑/赤ではない。
