# 047: プレミアムをやめたあと、無料枠を超える写真に鍵を掛ける

## 目的

**人間の指示。プレミアムをやめたペアが 100 枚持っていたら、無料枠（30 枚）を超える分は取り上げる。取り上げる前に ZIP で持ち出せる（046）。**

**「取り上げる」= 消すのではなく鍵を掛ける**（人間の絵 `プレミアム/03`: ぼかして「プレミアムで解放」）。
もう一度プレミアムにすれば戻る。実体は R2 に残る。

## 0. 先に決めたこと（A）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | いつ鍵が掛かるか | **free に戻ってから 30 日の猶予のあと**（`couple_plans.expires_at` から 30 日。手で free にしたときは `updated_at` から 30 日） | 持ち出す時間。決済（048）の「期間終了まで有効」の上に 30 日乗る |
| 2 | どの写真に鍵が掛かるか | **`taken_at` の古い順に 30 枚が残り、それより新しい分に鍵**（ペア全体。アルバムをまたいで数える） | 絵 `03` の並び（前が見えて後ろが鍵）。「最初に入れた 30 枚は無料」と一致する |
| 3 | 鍵の掛かった写真はどう見えるか | **一覧のマスに、ぼかした絵と鍵と「プレミアムで解放」**（絵 `03`）。押すと 045 のシート（`/premium` へ）。**ビューアで開けない・保存できない・ZIP に入らない** | 取り上げるとはそういうこと。ぼかしは**サーバが返す署名付き URL を出さない**ことで作る（画面で `blur` を掛けない。URL があれば取れる） |
| 4 | 鍵は行に持つか、読むときに計算するか | **読むときに計算する。**`album_photos` に列を足さない | 「free かつ猶予が過ぎた」は `couple_plans` だけで決まる。写真の行を書き換えると、戻すときにも書き換えが要る |
| 5 | 猶予の間の見え方 | **全部見える・保存できる・ZIP できる。**一覧とマイページに**「○月○日までに保存してください。それ以降、無料枠を超える写真は見られなくなります」**の帯 | 持ち出しの猶予だと分かる形 |
| 6 | 鍵の間に削除して 30 枚未満にしたら | 鍵が外れる（読むときに計算するので自然にそうなる） | 「自分で減らす」道を残す |
| 7 | 鍵の間に足せるか | **足せない**（045 の `PLAN_LIMIT`。`used` は鍵の分も数える） | 鍵の分を数えないと、鍵の上にさらに 30 枚積める |
| 8 | Cron・削除のジョブ | **持たない。**全部読むときの計算 | 消さないのでジョブが要らない。壊れる経路が 1 つ減る |
| 9 | 実体（R2）の費用 | 持ち続ける。鍵の分も消さない | 100 枚で数十 MB。「戻れる」価値の方が大きい |
| 10 | リリース履歴 | 入れない | 制限 |

## 1. 判定（サーバ）

`lib/plan.ts` の `resolvePlan(row, now)` を広げて **`PlanState`** を返す:

```
{ plan: "paid" }
{ plan: "free", lockAt: null }              -- 行が無い（最初から free）
{ plan: "free", lockAt: number }            -- paid だった。lockAt = 期限（または updated_at）+ 30 日。now < lockAt なら猶予中
{ plan: "free", lockAt: number, locked: true }   -- now >= lockAt。無料枠を超える分に鍵
```

- **鍵の対象**: ペアの未削除アルバムの `album_photos` を `taken_at, id` の昇順に並べ、**31 枚目以降**
- `photo.list`（アルバム）: 鍵の写真は **`url` を `null`**、`locked: true` で返す（`width`/`height`/`takenAt` はそのまま。マスの形を保つ）。**caption も返さない**
- `photo.downloadUrl`: 鍵の写真は `NOT_FOUND`（存在を教えない形に寄せる。`want.*` と同じ）
- `album.get` / `album.list`: `photoCount` は鍵を含む数。**`cover` が鍵の写真なら、鍵でない中でいちばん新しいものに倒す**（無ければ `null`）
- `couple.get`: `planState`（上の形）を返す。`albumQuota.used` は鍵を含む
- **判定は 1 箇所**（`lib/plan.ts`）。`photo.list` は「この写真が鍵か」を `lockedPhotoIds(coupleId, now)` の 1 関数から引く（31 枚目以降の id の集合。最大でも数百）

## 2. 画面

| 場所 | 猶予中（`lockAt` あり・未到達） | 鍵の後（`locked`） |
|---|---|---|
| アルバム一覧 | 使用量のカードの上に帯: 「**9月30日までに**写真を保存してください。それ以降、無料枠を超える写真は見られなくなります」+「ZIP で保存」（046）+「プレミアムについて」 | 帯: 「無料枠を超える 70 枚は見られません」+「プレミアムについて」 |
| アルバム詳細 | 同じ帯（短く） | 鍵のマス（絵 `03`）。押すと 045 のシート |
| マイページ | 同じ帯 | 同じ |
| ビューア | — | 鍵の写真はビューアに渡さない（`url` が `null` のものは開かない） |

- 日付は `packages/date` の `formatDateJa`
- 鍵のマスの絵: `surface-tint` の四角 + 鍵のアイコン + 「プレミアムで解放」。**元の写真をぼかして出さない**（URL を返していないので出せない。絵はぼかしているが、それは絵の都合）

## 3. やらないもの

| | 扱い |
|---|---|
| 実体の削除・Cron | しない（0節 #8・#9） |
| 鍵の写真の選び方を利用者に選ばせる | しない。古い順に 30 枚（0節 #2）。減らしたければ削除 |
| 猶予の通知（メール・プッシュ） | しない（`requirements.md` 5節）。帯で出す |
| タイムライン（投稿の写真）への鍵 | しない。投稿は制限しない |

## 4. テストで証明すること

| # | 何を | どこで |
|---|---|---|
| T1 | `resolvePlan`: 行なし → free/lockAt null。paid 期限内 → paid。期限切れ +29 日 → free 猶予中。+30 日 → locked。手で free（`updated_at`）も同じ | `apps/api` |
| T2 | locked で 40 枚: `photo.list` の 31〜40 枚目（`taken_at` 昇順）が `url: null, locked: true`、caption 無し。30 枚目までは URL あり。アルバムをまたいで数える | `apps/api` |
| T3 | locked で鍵の写真の `photo.downloadUrl` → `NOT_FOUND`。鍵でない写真は取れる | `apps/api` |
| T4 | locked でカバーが鍵の写真 → 鍵でない中でいちばん新しいものに倒れる | `apps/api` |
| T5 | locked で 10 枚消して 30 枚になる → 鍵が全部外れる。paid に戻す → 外れる | `apps/api` |
| T6 | locked で `addPhotos` → `PLAN_LIMIT`（`used` が鍵を含む） | `apps/api` |
| T7 | 猶予中は全部の URL が返る。`couple.get` の `planState.lockAt` が正しい | `apps/api` |
| T8 | 画面: 猶予中の帯に日付と「ZIP で保存」。locked で鍵のマスが出て、押すとシート。鍵のマスはビューアを開かない | `apps/app` |
| T9 | 別ペアの写真を数えない（`couple_id` スコープ） | `apps/api` |

## 確認観点

- 運営の SQL で `expires_at` を過去にして猶予 → 鍵の順に見える（人間のペアで 1 度だけ。終わったら paid に戻す）
- 鍵の写真は URL を持たない（ネットワークの応答で確かめる）
