# 017: 画像の全画面表示

## 目的
投稿カードの画像をタップして全画面で表示できるようにする。

**人間が 008・009 の実機確認中に出した要望**（L54）。写真を中心に据えたアプリで、
画像がカード内の縮小表示でしか見られないのは体験の欠落である。
マイルストーンの受け入れ判定が拾った要望なので、優先して入れる。

## 変更対象ファイル
- （新規）`apps/app/components/image-viewer.tsx`
- `apps/app/components/post-card.tsx` — 画像をタップで開く

## やらないこと（先に決める）

要望は「**X のように**全画面で拡大表示したい」だった。X の挙動を全部入れると
タスクが跳ねるので、**次の3つは入れない。**

| やらないこと | 理由 |
|---|---|
| ピンチズーム | `react-native-gesture-handler` + `reanimated` の導入が要る。**元画像は長辺1600px・JPEG品質0.8**（007）なので、深く拡大しても粗くなるだけで得るものが少ない |
| スワイプで閉じる | 同じくジェスチャライブラリが要る。閉じる導線は他に3つ用意する |
| 画像間のスワイプ移動 | 1投稿1画像なので移動先が無い（`requirements.md` 5節「1投稿に複数画像」はスコープ外） |

**全画面で画像全体が見えること**が要望の中心である。そこだけを満たす。
将来ピンチズームを入れるなら、先に画像の保存解像度を上げる判断が要る。

## 実装内容

### 表示は画面内の状態で行う。ルートを作らない

`react-native` の `Modal` を使い、タイムライン画面が状態として開閉を持つ。
**expo-router のモーダルルートにしない。**

理由は署名付きURLにある。`post.list` が返す GET URL は**既に手元にある**。
ルートにすると投稿IDからURLを引き直すことになり、**期限切れのURLを掴む経路を
新設する**（L46 と同じ形）。手元の値をそのまま渡す方が壊れにくい。

### 新しい API 手続きを作らない

`post.list` が返している署名付きGET URLをそのまま使う。
**認可の経路を1本も増やさない**（`security-requirements.md` 3節）。
未認証のデモ経路でも同じように開ける。

### 閉じる導線を3つ用意する

| 導線 | 備考 |
|---|---|
| 画像の外側をタップ | |
| × ボタン | `accessibilityLabel` を付ける |
| 端末の戻る / Esc | `Modal` の `onRequestClose`。**Android の実機とWebの両方で確かめる** |

**開く操作に二重発火のガードは要らない。** `conventions.md` 4節が対象にするのは
副作用のある操作であり、表示を開くことに副作用は無い。生の `Pressable` でよい。

### 表示

- 画像は**全体が見える形**で収める（`contain`）。切り取らない
- 背景は暗くし、画像の輪郭が分かるようにする
- 色は `packages/ui` のトークン経由。生の16進カラーを書かない

## 状態の網羅

008 と同じ考え方で、以下をすべて実装する。

| 状態 | 表示 |
|---|---|
| 読み込み中 | スピナー |
| 読み込み失敗 | 代替表示。**この状態でも閉じられること**（閉じられないと詰む） |

## 確認観点
- スマホ幅とPC幅の両方で、画像全体が画面に収まるか
- **縦長写真**で破綻しないか（`fix/compose-image-preview-layout` と同じ形の不具合）
- 閉じる導線3つがすべて効くか。特に Android の戻ると Web の Esc
- 読み込み失敗の状態から閉じられるか
- 生の16進カラーが混入していないか
- 新しい API 手続きを増やしていないか
