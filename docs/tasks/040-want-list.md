# 040: ほしいもの

## 目的

**人間の指示。「買ってほしい」ではなく、「こういうのが欲しいんだ」を相手に伝えるための一覧。**

- **URL（Amazon 等）を貼ると、小さく画像が見える**（Discord・LINE に URL を貼ったときと同じ見え方）
- **人物のタブで切り替える。初期表示は相手。自分を選ぶと追加ボタンが出る**
- **新しい順だけ。価格は持たない**（人間の決定）
- 絵は `docs/sample/simpleMode/新機能/…Wishlist….png`（人間が「これを使っていい」と言った）

## 0. 027「リスト」とは別の機能である

027 は**行きたい場所・食べたいもの**で、ふたりで共有し、どちらも達成にできる。
これは**個人のほしいもの**で、URL と画像を持ち、**書けるのは本人だけ**。

**表も手続きも別に切る。**027 の `wishes` に列を足さない（分類を持たないと決めた表に、
URL と画像と所有者を足すと別物になる）。

| | 027 リスト | **040 ほしいもの** |
|---|---|---|
| 主語 | ふたり | **本人** |
| 書ける人 | どちらでも | **本人だけ** |
| 中身 | 題名・メモ | **題名・URL・画像・メモ** |
| 終わり | 達成 | **手に入れた** |

**名前**: 機能名は「ほしいもの」。表は `wants`。契約は `want.*`。
「Wishlist」は既存の `wishes` と衝突するので、コードには使わない。

## 1. 画像はどこから来るか（この機能の要）

**2つの経路がある。どちらも同じ場所（R2）に落ちる。**

| 経路 | いつ | どうやって |
|---|---|---|
| **A. URL から自動** | URL を付けて保存したとき | **Worker がそのページを fetch し、OGP（`og:image`）の画像を取って R2 に保存する** |
| **B. 手で付ける** | 自動で取れなかったとき・URL が無いとき | 投稿写真と同じ経路（署名付き PUT）。スクリーンショットでも何でもいい |

**A が主役ではない。**Amazon は無名の fetch を弾くことがある（Discord・LINE は名前で通されている）。
**A が失敗しても、画像無しの行として保存は成功する。**そのあと B で付けられる。
**A の失敗で保存が失敗する形にしない。**

### 外部 URL の取得は、新しい口である

**利用者が書いた URL をサーバが fetch する。**この形の口は futary に初めて入る。
`security-requirements.md` 6節「外部 URL の取得」に要件を書いた。**実装はそれに従う。**要点:

- **`http:` / `https:` 以外は取りに行かない**（入力スキーマで弾く）
- **ホストが IP リテラル・`localhost`・`.local`・`.internal` なら取りに行かない**
- **リダイレクトは 3 回まで。行き先も同じ検査を通す**
- **ページは先頭 512KB まで読んで打ち切る**（OGP は `<head>` にある）。**全体の時間は 5 秒で打ち切る**
- **画像は `image/jpeg` `image/png` `image/webp` のみ、1MB まで。**超えたら画像無し
- **Cookie・認証ヘッダを送らない。**`User-Agent` は futary を名乗る（下記 2節）
- **失敗は画像無しで済ませる。**理由はログに残す（status・先頭 200 文字。AI まとめの修正と同じ形）

**サーバ側で縮小しない。**Workers に画像処理のライブラリは無く、Cloudflare Images は有料。
**1MB の上限で受け止める。**Amazon・楽天の `og:image` は数十〜数百 KB で収まる。

### 取ってきた画像は外部 URL のまま出さない

**CSP の `img-src` を外部ホストに開けない**（`build-public.mjs`「ワイルドカードで許可しない」）。
R2 に保存して署名付き URL で出す。**店が画像を差し替えても、ふたりの一覧は変わらない。**

### `og:title` も取る

題名の入力を省ける。**取れたら題名の初期値にする。**利用者が書き換えられる。
題名が空で `og:title` も取れなければ、**URL のホスト名を題名にする**（空の行を作らない）。

## 2. 段階0: Amazon が通るか測る（最初にやる。ここで一度止まる）

**作り込んでから「Amazon で半分失敗する」と分かるのがいちばん高い。**

B が最初に **1〜2 時間**でやること:
- Worker から Amazon の商品 URL を fetch し、`og:image` が取れる割合を測る
- **`wrangler dev --remote` か、実際にデプロイした Worker で測る。**ローカルの `wrangler dev` は
  自分の PC の IP から出るので、Cloudflare の IP から出る本番と結果が違う
- URL は 5 本 × 3 回。人間が貼ったもの（`https://www.amazon.co.jp/dp/B0HJBHHXK2/`）を含める
- **`User-Agent` を 2 通り試す**: (1) `futary-link-preview/1 (+https://<本番のURL>)`、(2) 一般的なブラウザの UA 文字列
- **Discord・LINE・Twitter・Facebook のクローラの名前は名乗らない。**それは偽装で、いつ塞がれるか分からない
- 楽天・一般の店（無印・ユニクロ等）も各 1 本

**結果を A に知らせて止まる。**A が決める:

| 結果 | 決定 |
|---|---|
| (1) で 8 割以上 | (1) で行く |
| (1) は駄目、(2) で 8 割以上 | (2) で行く。理由を `architecture.md` に書く |
| どちらも 5 割未満 | **A（自動）を入れない。B（手で付ける）だけで作る。**URL は文字として持つ |

**この判断は A の手番。B は測って止まる。**

## 3. データモデル

```sql
CREATE TABLE wants (
  id          TEXT PRIMARY KEY,
  couple_id   TEXT NOT NULL REFERENCES couples(id),
  owner_id    TEXT NOT NULL REFERENCES user(id),   -- 誰のほしいものか。作成者と同じ。変わらない
  title       TEXT NOT NULL,                       -- 1〜100 文字（trim 後）
  url         TEXT,                                -- NULL 可。http/https のみ。2048 文字まで
  note        TEXT NOT NULL DEFAULT '',            -- 0〜200 文字
  image_key   TEXT UNIQUE,                         -- NULL 可。R2 のキー。サーバが組み立てる
  created_at  INTEGER NOT NULL,
  obtained_at INTEGER,                             -- 非 NULL なら手に入れた。行は消さない
  deleted_at  INTEGER                              -- 論理削除
);
CREATE INDEX wants_couple_owner_created_idx ON wants (couple_id, owner_id, created_at DESC);
```

- **`owner_id` はレスポンスに出さない。**`isMine: boolean` と `ownerName` を返す（`createdByName` と同じ考え方。`architecture.md` 5節）
- **R2 のキー**: `couples/{coupleId}/wants/{imageId}.{jpg|png|webp}`。**`posts/` と分ける**
  （退会時の削除 `deleteAllByPrefix` の対象が分かる。`me.delete` に `wants/` の削除を足す）
- **`image_key` は投稿画像と違って拡張子が 3 種ある。**署名付き GET で `Content-Type` を正しく返す
- **上限: 1 人 100 件**（未削除・手に入れた分を含む。027 と同じ「上限を持ってページングを持たない」）
- **CHECK は持たない**（027 と同じ理由）
- `me.delete`: **`wants` の行と `wants/` の R2 オブジェクトを消す。**順序は既存の `wishes`・`moods` と同じ節に足す

### URL の正規化

**Amazon だけ**、`/dp/{ASIN}` を含む URL は `https://www.amazon.co.jp/dp/{ASIN}` に揃えて保存する
（`?tag=…&th=1` のような追跡パラメータを落とす。人間が貼った URL にもアフィリエイトの `tag` が付いていた）。
**他の店は触らない。**正規化の一般化はしない（店ごとの規則を集め始めると終わらない）。

## 4. 契約（oRPC）

| 手続き | 種別 | 入力 | 出力 | 備考 |
|---|---|---|---|---|
| `want.list` | read | `{ ownerSide: "me" \| "partner" }` | `{ items: Want[], ownerName }` | 未削除のみ。新しい順。**手に入れたものは末尾にまとめる**（027 と同じ）。**T9 の対象** |
| `want.create` | write | `{ title?, url?, note?, imageId? }` | `Want` | **`title` と `url` の少なくとも一方が要る。**`url` があり `imageId` が無ければ **A（自動取得）を試す**。`title` が無ければ `og:title` → ホスト名 |
| `want.update` | write | `{ id, title, url, note }` | `Want` | **本人のみ**。URL を変えても画像は自動で取り直さない（取り直したければ画像を外して付け直す） |
| `want.setImage` | write | `{ id, imageId \| null }` | `Want` | **本人のみ**。手で付ける・外す。`null` で R2 のオブジェクトも消す |
| `want.setObtained` | write | `{ id, obtained: boolean }` | `Want` | **本人のみ**。`toggle` にしない（027 3節） |
| `want.delete` | write | `{ id }` | `void` | **本人のみ**。論理削除 + R2 のオブジェクトは物理削除 |
| `want.uploadUrl` | write | `{ contentType: "image/jpeg" }` | `{ imageId, url }` | `post.uploadUrl` と同じ形。**手で付ける経路は JPEG のみ**（クライアントが圧縮する。ADR-007） |

- **本人でないときは `FORBIDDEN`**（`couple_id` は通るが `owner_id` が違う）。**存在しない id と、相手の id を区別しない**（`NOT_FOUND` に寄せる。存在の有無を漏らさない）
- `want.create` の A（自動取得）は**手続きの中で同期に待つ**（最大 5 秒）。**取れなくても 200 で返す。**`Want.image` が `null` なだけ
- **`Want.url` は `http`/`https` のもの以外は絶対に返さない**（クライアントが `Linking.openURL` に渡す。入力で弾いているが、出力でも `z.string().url()` + scheme 検査）

## 5. 画面

### 入口: ホームの機能パネルを 3 列 × 3 行にする

**今は 4 列 × 2 行の 8 枚。**9 枚目を足すと 4+4+1 で崩れる。**3 列 × 3 行にする。**
タイルが大きくなる（390pt で 1 枚約 110pt → 約 120pt）。**ピンクもホワイトも変わる。**
039 でピンクを凍結したのは 039 の範囲の話で、**機能が増えれば入口は変わる。**

- ラベル「ほしいもの」。**ホワイトの写真タイル**は `新機能/…Wishlist….png` を 600×600 JPEG に切り出す（039 と同じ置き方）
- **ピンクの線画アイコン**は `docs/sample/icon/` に無い。**既存の `panel-*.png` と同じ線の太さで B が1つ作る**（ハートか、リボンの付いた箱）。作れなければ `panel-list.png` を仮に置いて結果に書く
- 並び: 3 列目の末尾ではなく、**「リスト」の隣**（リスト → ほしいもの → 気分の記録 → AIまとめ）。近い意味のものを隣に

### 一覧: `(tabs)/want.tsx`（`href: null`。リスト・統計と同じ）

**モックの絵**: 白いカードの 2 列グリッド。**正方形の画像 + 題名。**価格は出さない（人間の決定）。

```
[ ゆい ]  [ れん ]          ← 人物のタブ（名前。相手が左・初期選択）
┌────────┐ ┌────────┐
│  画像  │ │  画像  │
│ 題名   │ │ 題名   │
└────────┘ └────────┘
                       (+)  ← 自分のタブのときだけ
```

- **タブは 2 つ。初期は相手。**1 人のペアなら自分だけ（タブを出さない）
- **画像が無い行**: `surface-tint` の地にリンクのアイコン（URL あり）か、何も無し（URL 無し）。**空の四角を出さない**
- **押す**: URL があれば **開く**（`Linking.openURL`。**新しいタブ／ブラウザ**）。URL が無ければ何もしない
- **長押し（Web は … ボタン）**: 自分の行だけ **「手に入れた」「画像を付ける／外す」「編集」「削除」**。相手の行は何も出ない
- **手に入れたもの**: 末尾に、薄く（`opacity` ではなく `muted` の題名 + 「手に入れた」のバッジ）。**消さない**
- **追加**: 自分のタブに **+ ボタン**（FAB ではなく一覧の上。FAB は投稿のもの）。押すと**モーダル**: URL（任意）・題名（任意。URL が無ければ必須）・メモ・画像（任意）。**保存すると閉じて一覧に出る。**A の取得に最大 5 秒かかるので、**保存ボタンは押下後に「取得中…」**
- **ゲスト（デモ）**: 見られる。書けない（`writeProcedure`）

### 文言

- 空の相手のタブ: **「まだありません」**
- 空の自分のタブ: **「URL を貼ると画像が付きます」**（+ ボタンの近く）
- 自動取得が失敗した直後: **「画像は取れませんでした。あとから付けられます」**（1 行。エラー扱いにしない）

## 確認観点

- 人間が貼った Amazon の URL で、**本番で画像が付く**（段階0の結果しだい）
- 相手のタブが最初に開く。自分のタブでだけ足せる
- 相手の行を長押ししても何も出ない
- 画像が取れなかった行に、あとから写真を付けられる
- 退会で消える（`wants/` に孤児が残らない）
- ホームの 3 列がピンク・ホワイトの両方で崩れない（iPhone 幅・PC 幅）
