# 011: カレンダーUI

## 目的
月表示のカレンダーで記念日・予定・会った日を見て、登録できるようにする。

## 変更対象ファイル
- （新規）`apps/app/app/calendar.tsx`
- （新規）`apps/app/components/month-grid.tsx`
- （新規）`apps/app/components/event-form.tsx`
- `apps/app/app/(tabs)/index.tsx` — ホームからカレンダーへの導線

## 実装内容
- 月表示のグリッド（日〜土）。前月・翌月へ移動できる

### `event.list` はグリッドの端から端まで取る

**月の初日〜末日で取らない。**グリッドには前月・翌月の日が入るので、
月の範囲だけで取ると**それらのセルが常に空になる。**
イベントがあるのに表示されない形で、バグとして気づきにくい。

グリッドの実際の範囲を実測した（日〜土）。

| 月 | グリッドの範囲 | 日数 |
|---|---|---|
| 2026年12月 | `2026-11-29 〜 2027-01-02` | 35 |
| **2027年1月** | `2026-12-27 〜 2027-02-06` | **42** |
| 2026年2月 | `2026-02-01 〜 2026-02-28` | **28**（前後に食い込まない） |
| 2028年2月 | `2028-01-30 〜 2028-03-04` | 35 |

- **年をまたぐ月がある。**`event.list` は年跨ぎを扱う（`architecture.md` 5節）ので
  1回で取れる。月ごとに2回呼び分けない
- **グリッドの日数は 28〜42 で一定しない。**42日固定で組むと 2026年2月のように
  ちょうど収まる月で余分な行が出る
- `event.list` の範囲上限は400日なので、月グリッドは常に収まる
- イベントのある日にマーカーを表示する。**種別ごとに色を変える**
  - 記念日 / 予定 / 会った日 が一目で区別できること
  - 色はトークンから取る。生の16進カラーを書かない
- 選択された日のイベント一覧を、カレンダーの下にカードで表示する
- 追加ボタンからイベントを登録する
  - 日付、タイトル、種別（記念日 / 予定 / 会った日）
  - 記念日を選ぶと `repeat_yearly` が自動で `true` になる
- 既存イベントの編集・削除
- カレンダーライブラリは**入れない**。月グリッドは自前で組む
  （React Native Web で動くカレンダーライブラリの選定と検証に時間を取られるため。
  月グリッドの描画自体は日付計算さえ正しければ単純）

## 実装メモ

- `apps/app/lib/calendar.ts`（新規） — 月グリッド（日〜土）の日付計算。
  `apps/api/src/lib/date.ts` とは依存関係が無い別ワークスペースのため、
  `todayJst` はここでも独立に実装している（重複だが、`apps/app` が `apps/api`
  に依存する経路が無い以上やむを得ない）
  - `monthGridRange(year, month)` — `event.list` に渡す `from`/`to`。
    タスクファイルの実測値（2026年12月・2027年1月・2026年2月・2028年2月）を
    そのままテストの期待値にした
  - `buildMonthGrid(year, month)` — グリッドの全日付をフラット配列で返す
    （28〜42件。7件ごとに折り返すと週になる。固定6行にしていない）
- `packages/ui/src/tokens.ts` に `colors.eventAnniversary` / `eventPlan` /
  `eventMeetup` を新設（017の `colors.overlay` と同じ形で `architecture.md`
  7節にも反映）。色だけに頼らず、グリフ（●/■/▲）とラベルテキストを常に併用する
  （`apps/app/lib/event-kind.ts`。確認観点「色覚特性に依存しない差」）
- `apps/app/components/month-grid.tsx` — 日付セルは `flex-wrap` で
  幅 `100/7%` を折り返す形にし、28日と42日のどちらでも余分な行を作らない
- `apps/app/components/event-form.tsx` — モーダルの背景は「親子の
  `Pressable` で `stopPropagation` する」形を避け、背景を独立した
  `absoluteFill` の兄弟レイヤーとして下に敷いた（017で当たり判定の穴を
  踏んだのと同じ理由の先回り。フォーム本体の入力欄・ボタンへのタップが
  背景の閉じる処理まで到達しない）
- **編集は射影後の表示日付（`event.date`）ではなく登録日（`event.sourceDate`）
  を対象にする。** 繰り返し記念日は照会範囲が触れる年ごとに射影されて返るため
  （010・architecture.md 5節）、今年に表示されている記念日の `date` をそのまま
  `event.update` に送ると、記念日の登録日そのものを今年へ動かしてしまう。
  `sourceDate` と `date` が異なる（＝射影された表示である）ときはフォームに
  注記を出す。`apps/app/test/calendar-screen.test.tsx` の
  「編集は射影日ではなく登録日を対象にする」で回帰を固定した
- ホームからの導線は `apps/app/app/(tabs)/index.tsx` のヘッダーに
  「📅 カレンダー」ボタンを追加する形にした（タブは5枠固定・FABが中央を
  占めるため、6つ目のタブは増やさない）
- `event.list` のキャッシュ無効化は `orpc.event.list.key()`（引数無し）で行う。
  月ごとに `from`/`to` が異なりクエリキーが分かれるため、特定の月だけでなく
  全ての `event.list` キャッシュを無効化する（`post.list` の既存パターンと同じ）
- E2Eテスト（画面結合テスト。conventions.md 6節の呼称）は
  `apps/app/test/calendar.test.ts`（純粋な日付計算11件）と
  `apps/app/test/calendar-screen.test.tsx`（画面結合8件。登録→反映、
  グリッド端（前月側）のセルにあるイベントが表示されること＝タスクの
  確認観点「前月・翌月の日のセルにイベントがあるとき、ちゃんと出るか」の
  自動回帰、記念日選択で`repeatYearly`が自動でtrueになること、
  射影日ではなく登録日を編集対象にすること、削除）を含む
- テストは apps/app 55件（既存36件+新規19件）・apps/api 181件（無変更）・
  packages/ui 7件（無変更）すべて緑。型チェック・lint通過
