# fix/profile-primary-date-wrap — 手動確認

実行日: 2026-08-30 / セッションB
発見経緯: 人間が実機（iPhoneサイズ）でマイページを確認し、「ホーム上部の
表示」を選ぶ3つのボタンのうち2つ（付き合った日・結婚した日）が、
単語の途中で2行に折り返されて見苦しいとスクリーンショット付きで報告した
（「付き合」「った日」のような割れ方）。

**Rレビューで同型の不具合が`event-form.tsx`（カレンダーの予定登録・種別
選択の3ボタン）にも見つかった。**幅の計算上、「会った日」も同じiPhone幅
（390px）では折り返す条件を満たしており、実際に崩れているが「付き合った」
より崩れ方が地味なため人間が気づいていなかった可能性が高いとの指摘。
同じPRであわせて修正した。

## 原因

`apps/app/app/(tabs)/profile.tsx`の3つの選択ボタンが、それぞれ
`<View style={{ flex: 1 }}>`で包まれ、幅を強制的に3等分されていた。
iPhone幅では1ボタンあたりの幅が「付き合った日」（6文字・16px太字）を
1行で収めるには足りず、`Button`内部の`Text`が折り返し、かつボタン自体の
横幅が狭いため単語の区切りとは無関係な位置で改行されていた。

## 修正

flex:1による均等割りをやめ、`flexDirection:"row"`+`flexWrap:"wrap"`の
コンテナに変更した。各ボタンは内容の幅で自然にサイズし、収まらない分だけ
次の行へボタン単位で折り返す（単語の途中では割れない）。`Button`・`Text`
コンポーネント自体は変更していない。

## 再発を防ぐ手段

自動テストとしての回帰テストは追加していない。ボタンが実際に何文字目で
折り返るかは実機のフォント計測・画面幅に依存し、jsdom結合テストの対象外
（`conventions.md`6節「レイアウトに依存する計算はテストできない」）。
`profile-screen.test.tsx`の既存9件（testIDでのクリック動作を検証）は
レイアウト変更を問わずそのまま通過した。

## 影響範囲

`profile.tsx`の「ホーム上部の表示」ボタン3つ、`event-form.tsx`（カレンダーの
予定登録モーダル）の「種別」ボタン3つ。同じ`flex:1`均等割りパターンを
アプリ全体でgrepし直し、他に該当箇所が無いことを確認した
（`compose.tsx`の2ボタンは幅に余裕があり対象外。Rが計算で確認済み）。
