# 033: 複数画像を横にスライド — テスト結果

## 0節（先に確かめたこと）

`artifacts/033/0-node-verification.md`参照。結論: **`ScrollView horizontal
pagingEnabled`はreact-native-web 0.21.2で効く。**中断せずそのまま進んだ。

## Aの指摘への対応

0節の実測直後、Aから「ページ幅＝コンテナ幅の設計のままでは『次の画像の端』が
見えない」と指摘を受けた。**子要素をコンテナより狭く**する設計へ変更
（`ROW_ITEM_WIDTH_RATIO = 0.88`。数値は仮置き、人間の実機確認で調整する
前提）。

## 実装

### 一覧（`apps/app/components/post-images.tsx`）

- **1枚のときは031から変えていない**（アスペクト比を保った単一表示）
- **2枚以上は横一列。指で送る**（`ScrollView horizontal pagingEnabled`）。
  031の正方形グリッドを覆した
- 各画像はコンテナ幅の88%。**次の画像の端が見える**
- **ドットのインジケータは置かない**（最大4枚。端が見えていれば続きが
  分かる。タスク定義2節）

**実装中に発見した不具合**: react-native-webの横スクロールの中身
（コンテンツコンテナ）は幅がコンテンツに合わせて伸びる「幅が定まらない」
コンテナになるため、子要素に`width:"88%"`のような文字列（相対）指定を
しても正しく解決されない。実測で、561px幅のコンテナに対し子要素が
本来494pxになるべきところ77pxほどにしかならないことを発見した。
**外側の幅が定まったViewを`onLayout`で実測し、そこから算出したpx単位の
幅を子要素に渡す形へ直した。** ライトボックス側（後述）にも同じ形の
不具合があり、同じ手法で直した。

### ライトボックス（`apps/app/components/image-viewer.tsx`）

- **スワイプで送れるようにした**（031のボタンのみから覆した）。**ボタンは
  残す**（PCからマウスで見る経路として）
- 何枚目かを出す（`n / 総数`）。031から変えていない
- **閉じる導線は017のまま3つ**（背景タップ・×ボタン・Esc/戻る）。
  **スワイプで閉じる操作は足していない**（横方向のPanResponderのみで、
  縦方向の処理を持たない）

**実装中に発見した不具合（重要）**: `react-native-web`の`ScrollView`は、
Web版のベース実装（`ScrollViewBase.js`）を実際に読んで確認したところ、
**内部で`onScroll`しか呼んでいない。**`onScrollEndDrag`・
`onMomentumScrollEnd`はScrollViewの外側の層にpropとして渡っているだけで、
Web版からは一度も呼ばれない（ネイティブ〈iOS/Android〉では実際のスクロール
終了イベントとして届くが、Webでは届かない）。**当初`onMomentumScrollEnd`を
使う設計にしていたが、実装時にソースを読んで気づき、`onScroll`（ドラッグ中も
含めて都度計算し直す。最後に呼ばれた値が着地点になるためデバウンスは
要らない）へ直した。**

## テストで証明すること（タスク定義）への対応

`apps/app/test/post-card.test.tsx`に追加・書き換え:

- **1枚のときの見え方が変わっていない**（既存の031テストがそのまま緑。
  `post-images-row`のScrollViewを使わないことも確認するテストを追加）
- **2枚以上で横に送れる**: `post-images-row`が存在し、ドラッグ（Browser
  paneでの実機確認）・スワイプ相当のスクロールイベントで送れることを確認
- **次の画像の端が見えている（構造として）**: `ROW_ITEM_WIDTH_RATIO`
  （export済み）が1未満であることを固定するテスト。実際の見え方は
  onLayoutに依存し jsdomでは測れないため、Browser paneでの実機確認
  （後述）と人間の実機確認で担保する
- **ライトボックスでスワイプとボタンの両方が効く**: DOM要素の
  `scrollLeft`/`offsetWidth`を直接差し替えてから`scroll`イベントを
  発火させ（`fireEvent`の`nativeEvent`引数はreact-native-webに読まれない
  ため。react-native-web内部の実時間デバウンスに引っかからないよう
  フェイクタイマーで100ms以上進める）、カウンターが更新されることを確認。
  続けてボタンでも送れることを確認
- **スワイプで背景タップの閉じる操作と混ざらない**: スワイプ後もモーダルが
  開いたままであることを確認
- **`react-native-gesture-handler`/`reanimated`を追加していない**:
  `apps/app/package.json`に変更なし（`git diff`で確認。今回の実装は
  React Native標準の`ScrollView`のみで完結している）

## Bによるブラウザでの確認

`wrangler dev` + `expo start --web`でBrowser paneから確認。

- 4枚投稿の一覧行で、各画像が実測494px（コンテナ561px×88%）になっている
  ことをDOM測定で確認（修正前は77pxしかなく、次の端どころか1枚もまともに
  見えていなかった不具合を実機で発見・修正した）
- ドラッグで一覧行を送れる（`scrollLeft`が0→1426〈末尾〉まで動くことを確認）
- 一覧行の画像をタップすると、その枚数目からライトボックスが開く
  （position=0の画像をタップして「1/4」で開くことを確認）
- **ライトボックス内でのドラッグは、このBrowser
  paneのマウス操作だとテキスト選択に化けて送れないことがあった**
  （実測。下記「分からなかったこと」参照）が、**マウスホイールでの
  横スクロールでは実際に送れ、カウンターが「1/4」→「2/4」→（ボタンで）
  「3/4」と正しく更新されることを確認した**
- モバイル幅（375×812）でも一覧行・単一画像の両方がレイアウト崩れなく
  表示される
- ライトボックスのbackdropが`<button>`ではなく`<div>`のまま（031で直した
  入れ子button問題が033で再発していない）ことをDOM測定で確認
- コンソールに033由来の新規エラーは出ていない

### 分からなかったこと（実機確認が必要）

- **ライトボックス内でのマウスドラッグ操作**が、このBrowser paneの
  自動操作では安定して再現できなかった（テキスト選択に化けることがある。
  ツール側の制約と考えられる。マウスホイールでの横送りは実機で確認できた
  ため、`onScroll`ハンドラ自体は実際に機能している）。**実機（トラック
  パッド・実タッチ）でのスワイプ操作そのものは人間の確認が必要**
- **端がどれくらい見えれば「続きがある」と気づくか**は、タスク定義の
  とおり実機でしか分からない（`ROW_ITEM_WIDTH_RATIO=0.88`は仮置き）

いずれも`artifacts/033/manual-check.md`に人間への確認項目として列挙した。

## security-auditorの監査

**High・Medium以上はゼロ。**Low 5件のうち4件をその場で修正した
（詳細は`artifacts/033/security-audit-raw.md`）:

1. `index`のクランプが`handleScroll`の1箇所にしか無かった →
   `safeIndex`を描画・ボタン判定・カウンター全てで経由させ、
   `images.length`変化時のリセットも追加
2. 読み込み失敗の記録（`failedIndexes`）が添字キーで、署名付きURLが
   1時間で失効したあと新しいURLが届いても回復しない経路があった →
   URL自体をキーにして自然に再挑戦する形へ変更
3. **デスクトップのマウスドラッグが「閉じる」として誤発火しうる不具合を
   実機で確認・修正した。** press開始からclickまでの間に`onScroll`が
   起きていれば閉じないガードを追加。修正前後をBrowser paneで実際に
   ドラッグして確認済み（下記）
4. `postImageSchema.url`に形式の制約が無かった → `z.string().url()`を追加
5. （Low1件は031と同じ既存パターンのため記録のみ・対応なし）

修正後、`pnpm -r test`・`pnpm -r type-check`・`pnpm -w eslint .`を再実行し
全て通過。Browser paneで、修正前は誤って閉じていたテキスト上のドラッグ操作が
修正後は開いたままになることを実機確認した。
