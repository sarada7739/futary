# 011: カレンダーUI — 人間の実機確認（未実施）

カレンダー画面は認証必須（`Stack.Protected guard={hasCouple}`）のため、
Google OAuthログインを要する。B（自動化）はこの経路を通れない
（003・004・007と同じ制約。conventions.md 8節）。

自動テスト（`apps/app/test/calendar.test.ts`・`calendar-screen.test.tsx`。
`artifacts/011/test-results.md`参照）で担保しているのは oRPC クライアントを
モックした画面結合の配線までで、**実データ・実機での見た目は未確認。**

## 確認してほしい項目

1. `wrangler dev --remote` でログインし、ホーム画面「📅 カレンダー」から
   カレンダー画面を開ける
2. 前月・翌月への移動が正しく動く（月境界・年またぎ〈12月↔1月〉を含む）
3. イベント（記念日・予定・会った日）を登録・編集・削除でき、D1に反映される
4. 種別が色（`colors.eventAnniversary`/`eventPlan`/`eventMeetup`）とグリフ
   （●/■/▲）の両方で見分けられる。色覚特性のシミュレーション等での確認が
   できればなお良い
5. 繰り返し記念日が翌年以降も表示される
6. スマホ幅で7列グリッドが窮屈になっていないか（実機・レスポンシブ双方）
7. 前月・翌月にはみ出したグリッドのセルにイベントがあるとき、実際に表示されるか

## 進め方

条件を満たしたことにはしない。この節はチェックを付けず、`docs/state.md` の
未解決の論点に本タスクを起票する。マイルストーン（M3）の受け入れ判定で、
他タスク分とまとめて人間が実機で回収する（conventions.md 8節の手順）。
