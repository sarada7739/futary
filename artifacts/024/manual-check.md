# 024: アカウント削除と退会 — 人間の実機確認

マイページ・アカウント削除画面は認証必須のため、B（自動化）はブラウザで
直接開いて確認することができない（`CLAUDE.md`「Bは自分の実装を自己採点
しない」）。自動テストで担保しているのは契約・DB制約・削除順序・冪等性・
画面結合（モック経由）までで、実機での見た目・実際の削除の挙動・
リモートD1への影響は未確認。

**本番で試す前に、ローカルで一度も試していない状態から実際に削除を
実行し、結果を確認してほしい**（タスク定義の停止条件。「本番の削除は
やり直しがきかない」）。

## 確認してほしい項目

1. マイページ下部に「アカウントを削除」が出るか
2. 押すと、何が消えるかを列挙した段階1の画面に来るか
3. 「次へ」を押すと、相手のデータも消えること・相手には事前に知らせない
   ことが書かれた段階2の画面に来るか
4. チェックを入れるまで「ふたりのデータを削除する」ボタンが押せないか
5. 実際に削除を実行し、以下を確認する（**テスト用のペアで。取り消せない**）
   - 削除した本人がログアウト状態になり、サインイン画面に戻るか
   - 投稿・カレンダー・記念日・統計が消えているか（相手のアカウントで
     確認）
   - 招待コード（もしあれば）が使えなくなっているか
   - 相手のプロフィール画像・自分のプロフィール画像がR2から消えているか
     （Cloudflareダッシュボードで確認できると確実）
6. 削除した後、同じGoogleアカウントで再度ログインし、「初めての利用者」
   として登録し直せるか（前のペアの情報が一切出てこないか）
7. 相手の端末で、削除後にアプリを開くとどう見えるか（何も無い状態、
   オンボーディング画面になるはず）

## 特に確認してほしいこと（タスク定義の停止条件）

- ローカル環境で、削除の途中（例: 投稿を消した直後）でサーバを止めて
  から、もう一度「アカウントを削除する」を実行し、最後まで完了するか
- 上記を確認できたら、本番で実際に削除を試してよい

## 既知の制約（受け入れている挙動）

- ~~削除処理が`couple_members`を消した直後・`couples`の行を消す前で
  中断すると、`couples`の行が孤児として残る~~ → **解消済み（Rレビュー指摘。
  security-auditor指摘を受けてreactions〜couplesをdb.batch()1本に原子化
  したため）。** 途中で止まる窓自体が無くなり、当初「残る」と受け入れて
  いたこの孤児couples行も同時に解消された（`apps/api/src/procedures/

  現時点で無い

## 追記（2026-09-01・再認証まわり）: 確認してほしい項目

Aの判断（PR #186・#187）でme.deleteに再認証を追加した。この経路は
実際のGoogle OAuthセッションが要るため、Bのブラウザ確認（未認証のみ）
では通せない。

8. サインイン直後にアカウント削除画面を開き、通常どおり段階1の画面が
   出るか（「もう一度ログインしてください」に落ちないこと）
9. 直近のサインインから5分以上経った状態で開くと、段階1の代わりに
   「もう一度ログインしてください」の画面になるか
   - ローカルで再現する場合: ログイン後、ローカルD1の`session`テーブルの
     対象行の`created_at`を現在時刻から5分以上前の値に書き換えてから
     アカウント削除画面を開く
     （`npx wrangler d1 execute <DB名> --local --command "UPDATE session SET created_at = created_at - 600 WHERE user_id = '...'"`）
10. 「もう一度ログインする」を押すとGoogleのログイン画面に遷移し、
    完了すると削除画面に戻ってくるか（戻り先は`resolveReauthCallbackURL`。
    ネイティブでは`/delete-account`、Webでは`{origin}/app/delete-account`）
11. 再ログイン後、通常どおり段階1の画面に進めるか（`sessionIsFresh`が
    trueに戻っていること）
12. （やり切れれば）サーバ側の最終防御を直接踏む: 確認画面を開いたまま
    5分以上待ってから「ふたりのデータを削除する」を押し、
    `REAUTH_REQUIRED`を経て「もう一度ログインしてください」に切り替わるか
    確認する。時間がかかるため優先度は低い
