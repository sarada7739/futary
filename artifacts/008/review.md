コードを読む限り配線は正しく見えます。
```js
const deletePost = useMutation(orpc.post.delete.mutationOptions({
  onSuccess: () => queryClient.invalidateQueries({ queryKey: orpc.post.list.key() }),
}));
```
しかし `queryKey` の取り違えやメニューの未接続は、**読んだだけでは分かりません。**

### 人間の手は借りずに済みます

**画面結合テストを1件足してください。** `home-timeline.test.tsx` は既に oRPC クライアントをモックしているので、削除メニュー押下 → `post.delete` が呼ばれる → 一覧から消える、を書けるはずです。人間に追加の操作を頼む必要はありません。

スクリーンショットを撮らない方針になった以上、**UI の担保は自動テストに寄せるしかありません。** そこに削除だけ穴が空いているのは、方針変更で最も影響を受ける箇所です。PR #67 で「初見のレビューによる検出が失われる」と書いたばかりで、その穴が最初に出たのがここだと考えてください。

## 記録: 無限スクロールがどちらのリストにも無い

完了条件の1つ目は「投稿一覧が表示され、**無限スクロールが動く**」です。

証跡は「投稿一覧が表示された」とだけ書いており、**無限スクロールは「確認できたこと」にも「確認できていないこと」にも入っていません。** 投稿が20件未満なら次ページ自体が発生しないので、おそらく踏んでいないはずです。

分類漏れです。「確認できていないこと」に足してください。**この証跡の価値は網羅性にあります。** 抜けがあると、読んだ人が「書いていないことは確認済み」と誤読します。「4状態」「スマホ幅」を正直に挙げているだけに、ここだけ落ちているのがもったいない。

（無限スクロールもテストで担保できます。`getNextPageParam` とカーソルの受け渡しは結合テストで書ける範囲です。ただし完了条件を満たす最低限は削除の方なので、そちらを優先してください。）
