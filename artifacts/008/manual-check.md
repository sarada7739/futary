# 008: タイムラインUI — 人間の実機確認の記録

実施日: 2026-08-30
環境: `wrangler dev --remote`（実クラウド接続。L34解決後）+ `pnpm --filter @futary/app run web`、
Google OAuthで実際にログイン。

`conventions.md` 8節の方針により、スクリーンショットではなくこの記録（テキスト）を
証跡とする。

## 確認できたこと

- **ログイン**: Google OAuthで実際にログインできた
- **タイムライン表示**: 投稿一覧が表示された（テキストのみの投稿、画像付き投稿の
  両方が表示されることを確認。投稿者名・相対時刻の表示も確認）
- **投稿作成（画像付き）**: 画像を選んで投稿でき、一覧に反映されることを確認。
  当初は投稿作成画面のレイアウト崩れ（`fix/compose-image-preview-layout`で修正）と
  画像アップロード失敗（R2のCORS未設定・リモートD1のマイグレーション未適用が原因。
  L34参照）があり、いずれも修正後に成功を確認した
- **投稿作成（テキストのみ）**: 本文だけの投稿ができ、一覧に反映されることを確認
- **リアクション**: ハートボタンのタップで付与・取り消しができることを確認。
  当初タップ時に投稿一覧の画像がちらつく不具合があり、修正後に解消を確認した
  （009・`onSettled`削除）

「動作確認問題なし」との総合評価を得た。

## 確認できていないこと

- **投稿の削除（UI操作）**: UIから削除ボタンを操作して投稿が消えることは、この
  セッションでは人間による目視確認をしていない。`post.delete`のサーバ側ロジック
  （D1の論理削除・R2の`env.BUCKET.delete()`）は自動テストと、Rレビュー指摘を受けた
  一時デバッグルートでの実クラウド確認（`artifacts/007/manual-check.md`参照）で
  担保しているが、UI操作からの一連の流れ（削除メニュー→確認→反映）は目視確認が
  済んでいない。**【追記】Rレビューで、この一連の流れを検証する自動テストも
  1件も無いことを指摘され、`home-timeline.test.tsx`に画面結合テストを追加した
  （削除メニュー押下→`post.delete`呼び出し→一覧から消えることを確認）。人間の
  目視は依然として未実施だが、自動テストでの担保は追加した**
- **無限スクロール**: 完了条件の1つ「投稿一覧が表示され、無限スクロールが動く」の
  うち、無限スクロール自体はこのセッションで確認していない（投稿数が1ページ
  〈20件〉未満のため次ページ取得が発生しなかった）。**【Rレビュー指摘で分類漏れと
  判明】** 当初この項目自体が本節に無く、「書いていないことは確認済み」と誤読
  される状態だった
- **状態表示**（読み込み中・投稿ゼロ・通信エラー・画像読み込み失敗）: 画面結合テスト
  （`apps/app/test/home-timeline.test.tsx`）では確認しているが、実機での目視は
  していない
- **スマホ幅・PC幅両方でのレイアウト確認**: 実機確認はブラウザ幅（PC相当）で行った。
  スマホ幅での確認はしていない
