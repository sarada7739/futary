# 014: ゲスト・デモ体験 実機確認項目

B（自動化）が診断できた範囲と、人間の確認が要る範囲を分けて書く
（`conventions.md`「検証の範囲から外したものは、結果に書く」）。

## Bが自動化で確認済み（Claude in Chrome経由）

`wrangler dev --local` + Expo Web（`pnpm --filter @futary/app run web`）を起動し、
未認証のままブラウザで以下を確認した（データは `artifacts/014/test-results.md` 参照）。

1. サインイン画面の「ゲストではじめる」を押すとホームに入り、デモバナー
   （「これはデモです。ログインすると自分のふたりの記録を残せます」）が常時表示される
2. ホーム上部にデモペア（ゆい・れん）のアバター・「付き合って561日目」・「会った日数：94日」が表示される
3. タイムラインで投稿一覧（本文・投稿者名・日付）が表示される。1ヶ月前のマイルストーン投稿が確認できた
4. カレンダーで会った日・予定・記念日のマーカーが混在して表示される
5. FAB（＋投稿）を押すと、投稿画面を開かずサインイン画面へ戻る
6. カレンダーの「＋追加」ボタンが「ログインして追加」の表示になり、押すとフォームを開かずサインイン画面へ戻る
7. マイページはプロフィール編集フォームの代わりに「マイページはログインすると使えます」の案内が出る

## 人間の確認が要る（実機・実ブラウザ）

**この検証環境（Claude Code のBrowser pane・sandboxed preview）で、Metroの開発サーバへの
WebSocket接続が不安定になり（`Disconnected from Metro (1006)`が繰り返し発生）、
以降の追加確認が信頼できなくなった。** 上記1〜7は接続が安定していた時間帯に確認できたものであり、
それ以降の追試は打ち切った。**実際のブラウザ（この検証環境の外）ではこの不安定さ自体が
再現しない可能性が高い**が、以下は人間の実機で確認してほしい。

1. **既知の制約**: 一度ゲストモードを抜けて（FAB・カレンダー「＋追加」・マイページの
   いずれかを押してサインイン画面へ戻ったあと）、**同じページを再読み込みせずに**もう一度
   「ゲストではじめる」を押すと、デモバナーだけ表示されてサインイン画面のまま遷移しない
   ことがある（Expo Routerの`Stack.Protected`が、guardが新しくtrueになったグループへの
   自動遷移をサポートしていないため）。**ページを再読み込みすれば復帰する。**
   sessionStorage経由でのフルリロード方式を試したが、上記の接続不安定さと絡んで
   検証環境では確認しきれなかったため、単純な状態管理に戻して確実な方（初回の遷移）を優先した。
   **実際のブラウザでこの制約が実害になるか（頻度・気づきやすさ）を見てほしい。**
   気になるようであれば、`apps/app/app/_layout.tsx`のコメントに残した方針
   （sessionStorage + フルリロード）で再度直すことができる
2. ローカル開発では投稿画像・アバターが「画像を読み込めませんでした」と表示される。
   これは既知の制約（署名付きURLは常に実際のCloudflare R2のS3互換APIを指すため、
   `wrangler dev --local`のローカルR2には存在しない）であり、**014のバグではない**。
   本番投入（016）後、実際のR2に画像が入っていれば正しく表示されるはず
3. スマホ幅での表示（デモバナー・ホーム・タイムライン等の折り返し）
4. iOS Safari等、Chrome以外のブラウザでの動作
